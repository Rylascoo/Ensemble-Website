# Prelaunch Website Successor 01 — Design Review

Status: **REVIEW-READY DESIGN CANDIDATE / NOT PUBLISHED**

## Review frame

This is reviewed as the proposed replacement for the existing single-screen `www.kymaean.com` placeholder.

It is **not** reviewed as:
- a mascot campaign;
- an app UI mockup;
- a full launch website;
- final product information architecture;
- a Store/download page.

## What the current placeholder does well

The live V2.2 placeholder has four core strengths worth protecting:

1. **Identity restraint** — KYMÆAN is immediately legible and not surrounded by marketing clutter.
2. **Stage authority** — the visual world carries more weight than interface chrome.
3. **Negative space** — darkness feels intentional and cinematic.
4. **Mystery** — the visitor is not told more than the unfinished product can currently prove.

The successor should preserve all four.

## What the current placeholder cannot do

It does not tell a new visitor:
- what Kymaean broadly is;
- why persistent characters matter;
- why consequence matters;
- what local-first means;
- how creator authority differs from passive AI generation;
- what platform is being targeted.

A replacement needs to add product comprehension without converting the site into documentation.

## Candidate assessment

### Hero — retain

The hero remains visually descended from the current site:
- Stage first;
- wordmark centered and separate from the artwork;
- no product screenshot;
- no mascot;
- no decorative interface shell.

The added tagline and one-line descriptor are enough to answer "what is this?" without turning the hero into a conventional SaaS headline stack.

### A living Production — retain

The abstract Stage field introduces people + conditions without claiming a final application layout.

This is preferable to the historical seven-primitives grid for the current prelaunch site because it communicates the product thesis before internal ontology.

### People, not prompts — retain

This is the strongest product-distinction section.

The visual treatment deliberately avoids:
- portraits;
- character cards;
- fixed colors as identity;
- model/provider badges.

The message remains about persistence.

### Scar Bloom / consequence — retain

This is the most distinctive transition in the page.

It makes the visual system itself behave according to the product thesis: an earlier condition physically changes what follows.

The limestone field earns its material shift because it represents consequence rather than a generic light-theme section.

### Creator authority — retain

The section says only what is constitutionally stable.

The abstract scene prevents the site from inventing final creator controls.

### Local-first — retain with refined copy

The initial research wording was technically correct but too implementation-facing.

The revised public copy keeps:
- local sovereignty;
- creator control;
- bounded context for external models;

without describing provider architecture.

### Closing identity — retain

The page should end quietly rather than with an invented preorder/signup CTA.

Returning to the wordmark + Coming Soon makes the page still feel appropriate before Alpha availability.

## Copy-density audit

Visible prose is intentionally sparse.

The page is designed to be understood through:
- large headings;
- material sequence;
- short paragraphs;
- negative space;
- visual continuity.

It should not gain:
- feature bullets;
- FAQ content;
- provider logos;
- pricing;
- Store badges;
- screenshots;

until product and release authority supports them.

## Accessibility/static audit

Current candidate includes:
- one semantic H1;
- section H2 structure;
- decorative hero art with empty alt text;
- no form/button traps;
- keyboard-visible internal scroll link;
- reduced-motion fallback;
- forced-colors fallback;
- safe-area awareness;
- responsive phone/tablet layout.

Static audited contrast pairs:
- primary light on void: ~16.17:1;
- supporting text on void: ~7.58:1;
- stone ink on limestone: ~10.35:1;
- supporting stone text: ~4.79:1.

These are static color checks, not a claim of complete accessibility conformance.

## Responsive assessment

Desktop:
- full Stage field remains the opening authority;
- sections use large spatial composition rather than card rows.

Portrait:
- inherits the 148vw Stage framing selected in earlier context research;
- no tablet-specific progressive zoom;
- two-column sections collapse rather than miniaturize;
- character field becomes stacked structural bands;
- consequence scar stays off-center.

## Current weaknesses to watch in visual review

1. The fixed topbar adds a second KYMÆAN text presence above the large hero wordmark. This may be acceptable navigation anchoring, but if the opening feels too branded, the top-left text is the first element to remove.
2. The "People, not prompts" section must not become visually diagrammatic when rendered at real viewport sizes.
3. Limestone should feel like material consequence, not a theme toggle.
4. The page must retain enough silence between sections; do not compress vertical spacing merely to shorten scroll.
5. The Stage carrier is still a non-production diagnostic master. Final public encoding is a separate performance/asset gate.

## Recommendation

**Retain this candidate as the leading mascot-free prelaunch website successor.**

Next work should be a browser-scale visual integration pass against representative desktop and portrait dimensions, followed by only targeted refinements.

Do not add mascot integration, product screenshots, additional sections, navigation complexity, or feature exposition during that pass.
