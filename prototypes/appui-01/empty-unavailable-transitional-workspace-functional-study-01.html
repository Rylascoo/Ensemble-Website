B

State families — each explains a different application condition

Absence, loading, unavailable capability, failure and provisionality are not interchangeable.

Empty / none selected

No active Scene or no selected entity is a valid state. The shell names what is absent and keeps meaningful Production context reachable.

Empty ≠ error.

Loading / transitional

A task may be temporarily unavailable while application work is in progress. Prior semantic origin and focus-return target remain retained where possible.

Loading ≠ fictional delay.

Capability unavailable

A requested provider/capability may be unavailable. The application blocks before fiction and exposes truthful technical explanation or alternatives.

Unavailable ≠ Character refusal.

Cancelled / failed attempt

A failed or cancelled application attempt does not imply accepted Production change, Character action, consequence or history.

Failure ≠ narrative event.

Provisional / non-effective

Material awaiting a Product-defined authority/effect boundary stays visibly non-effective and cannot masquerade as current accepted state.

Provisional ≠ current/effective.

D

Boundary rules — missing capability and missing fiction are different

The application must not narrativize its own infrastructure.

Unavailable provider ≠ Character refusal

Capability/provider failure cannot be rendered as silence, refusal, incapacity, emotion or other fictional behavior.

Loading ≠ performed waiting

Application delay does not create fictional time passage, waiting, hesitation, relationship change or causal movement.

Empty ≠ deleted

No active Scene or no selection does not imply missing Production data, deleted Characters or erased history.

Failure ≠ consequence

A cancelled/failed technical attempt cannot enter causal history or consequence state unless Product authority separately accepts a real Production mutation.

F

Section laws and explicit non-authority

State grammar is resolved; lifecycle and provider mechanics are not.

One shell survives state changes

Empty, loading, unavailable, cancelled/failed and provisional conditions do not require a different application information architecture.

Infrastructure stays outside fiction

Provider/runtime/recovery state cannot become Character behavior, fictional causality or accepted Production history merely because it blocks a task.

Current and provisional remain distinct

Work awaiting Product-defined authority/effect semantics stays visibly non-effective and does not masquerade as accepted current state.

No invented Scene lifecycle

No active Scene is represented truthfully without freezing Create/Start/Resume/Take/branch/rehearsal controls or their labels.

Task return is part of recovery

When a transient or failed state ends, the prior semantic origin and focus are restored when still valid instead of dropping the creator into an unrelated dashboard.

Final visual language remains later

Exact icons, progress treatment, error styling, notifications, typography, palette, motion, native WinUI behavior and Phase-2 Stage visuals remain open.
