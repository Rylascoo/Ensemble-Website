B

Exception-state grammar — six infrastructure witnesses stay semantically distinct

The Stage may retain context while application truth changes around it.

Healthy / quiet

No intervention and no permanent “all changes saved” footer merely because persistence exists.

Persistence in progress

Application work in progress is not fictional delay and does not advance Scene time.

Capability unavailable

Technical unavailability is not Character refusal, incapacity, silence or fictional absence.

Persistence failure

Failure to persist is explicit application status and does not itself establish corruption.

Integrity concern

Corruption/integrity concern is distinct from persistence failure and does not become story damage.

Read-only / recovery needed

Creator action may be constrained by application truth without rewriting Character agency or Production history.

C

Stage origin → exception → truthful explanation → recovery outcome → exact return

Return restores application context when safe; it is not a Take, rewind, replay or Undo.
01 Stage origin

Production, Scene, current/selected state and keyboard focus have a known origin.

02 Exception

Infrastructure condition interrupts or blocks application work outside the fiction.

03 Explain truth

Application status identifies unavailable, failed, read-only or recovery-needed condition without invented narrative.

04 Resolve or remain unresolved

Product-defined recovery may succeed or the issue may remain explicit; neither outcome fabricates performance.

05 Exact return

When safe, return restores prior task/context/focus. Close/Back does not confirm durability or undo accepted Production truth.

D

Explicit non-authority — presentation does not define recovery implementation

This study inherits Phase-1 exception law; it does not promote Product/runtime mechanics.

No retry/fallback policy

No retry button behavior, provider fallback, cancellation, timeout, progress or automatic recovery algorithm is frozen.

No storage semantics

No autosave/save-point, transactionality, local/cloud, backup, conflict or durability guarantee is inferred.

No fictional consequence

Technical failure cannot create dialogue, silence, refusal, Scene history, accepted consequence or Character incapacity.

No Stage restart semantics

Recovery does not imply restart Scene, Another Take, rehearsal, branch, timeline rollback or replay.
