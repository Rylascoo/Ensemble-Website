PURPOSE
`intelligence/` is the explicit non-public control-plane namespace for website/design/repository intelligence in `Rylascoo/Ensemble-Website`.

It exists to make the operational boundary obvious without mass-moving the established `docs/`, `tools/`, `assets/` or `prototypes/` evidence graph.

AUTHORITY MAP
- Volatile current design/website boundary: `../CURRENT_STATE.md`.
- Durable repository workflow: `../AGENTS.md`.
- Design law, methods, handoffs and evidence: `../docs/`.
- Durable closure/re-entry history: `../docs/evidence/DESIGN_LEDGER.md`.
- Repository/design tooling: `../tools/`.
- Visual-master/provenance workspace: Google Drive `Ensemble Project`.
- Product/backend/runtime/engineering authority: `Rylascoo/Ensemble-Project`.

BACKEND INTELLIGENCE BOUNDARY
Do not build or mirror the product's runtime backend, provider orchestration, application services or engineering implementation here. Those remain owned by `Rylascoo/Ensemble-Project` unless the Director explicitly changes repository ownership.

In this repository, “intelligence” means the non-deployable control plane that informs website/design decisions. It is intentionally outside `site/` so Cloudflare publication cannot accidentally ingest project reasoning, evidence or internal tooling.

GOING FORWARD
Use this namespace as the clear entry point when a task asks for “website intelligence,” “design intelligence,” repository architecture, publication-boundary reasoning or cross-repository authority mapping.

Do not migrate existing canonical documents here merely for tidiness. A future migration is worthwhile only if it preserves document identity, inbound links, generated index behavior and historical evidence without weakening retrievability.
