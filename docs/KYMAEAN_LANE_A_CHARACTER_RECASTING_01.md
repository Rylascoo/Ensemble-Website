## Purpose

Refine O0 Character identity + Performer Assignment so the same Character remains recoverable across recasting and color loss:

```text
persistent Character identity
+ separate Performer Assignment
-> prepare recast
-> explicit future Performance boundary
-> new Performer assignment
+ unchanged Character identity/history
```

## Authority contract

- Character != Performer; Character != Portrait.
- Recasting changes who portrays a Character; it does not create, clone, reset, or rewrite the Character.
- Performer changes take effect only at an explicit Performance boundary, never mid-Performance.
- Existing accepted history remains attributed to the same Character.
- Provider/model data is secondary casting infrastructure and must not become persistent Stage identity.
- Identity, Presentation Perspective, Current Opportunity, Performance lifecycle and technical capability remain independent state channels.

## Identity test

The Stage test uses a redundant bundle:

> **name + distinct shape + accessible textual identity**

The three geometric marks are test instrumentation, not selected Character symbols or personality archetypes. Direct association in the living field preserves the earlier CIR result without restoring a permanent duplicate roster.

A manual monochrome state gives all three Character volumes the same luminance/color. Marlowe, Dr. Voss and Wren remain visually separable by shape and explicitly by name. This is design evidence only, not forced-colors/device validation.

`Prepare recast` -> choose a future Performer -> `Confirm recast`.
