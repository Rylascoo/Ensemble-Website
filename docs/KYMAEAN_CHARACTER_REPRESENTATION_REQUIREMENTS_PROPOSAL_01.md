## 0. Purpose

Define the minimum jobs a Kymaean Character representation must perform before the project explores portrait style, user-supplied imagery, AI-assisted imagery, illustration, reduced figurative systems, mixed representation depth, or other visual media.

This proposal intentionally separates:

```text
WHAT A CHARACTER REPRESENTATION MUST COMMUNICATE
from
HOW A CHARACTER IS DRAWN / PHOTOGRAPHED / GENERATED
```

It does **not** select:

- photorealism;
- illustration;
- 3D avatars;
- fixed portraits;
- generated portraits;
- user-uploaded reference images;
- a final Character creation workflow;
- a final Stage composition;
- palette, typography, material, iconography, motion, clothing, environment, camera language, or generated cast;
- facial-expression analysis, emotion recognition, gaze inference, body-language inference, or private-psychology visualization;
- production XAML/C#/Astro/CSS/JS.

## 2. Patch 0014 visual correction

Patch 0014 materially strengthens the privacy/epistemic boundary for visual design.

Current frozen/implemented laws include:

- Production-backed Access is derived from the exact current Production state;
- `HistoricalTruth`, `UnresolvedProposition`, and `WorldState` remain denied to a Character;
- another Character's owned subjective material remains denied;
- `CharacterClaim` disclosure remains deferred;
- current recall is not inferred merely because a CharacterClaim exists;
- observation is **not** inferred from co-presence, Candidate visible text, addressed Characters, nomination, Director selection, relationships, SceneState, or causal adjacency;
- `SourceStateHash` is authority metadata and never enters Character-facing rendered text;
- `recentPerformances` remains empty in the currently frozen Context v2 contract.

Visual consequence:

> **A Character representation may communicate identity, presence, spatial/relational position, and explicit system state, but it may not silently manufacture knowledge, observation, belief, intention, emotional certainty, or private psychology from pose or proximity.**

Therefore:

```text
looking toward someone
!=
knowing what they know

being present
!=
observing every event

holding Current Opportunity
!=
wanting to act

being visually central
!=
being psychologically dominant
```

This is a hard anti-hallucination requirement for the visual system.

## 3. Minimum jobs of a Character representation

A Character representation must perform six jobs reliably.

### CR-1 — Persistent identity

The creator must be able to recognize the same Character across:

- Stage / current Scene;
- Character-bounded perspective;
- history / causal trace when that surface is later designed;
- changed-present states;
- different scale, crop or density;
- accessibility/reduced-detail variants;
- future representation-depth changes.

Recognition must not depend on one immutable portrait.

Required law:

> **Identity is a redundant invariant bundle, not a single image.**

Candidate invariant families may include, depending on the chosen medium:

- name / textual identity;
- silhouette / body proportion;
- facial structure when a face exists;
- hair geometry;
- garment construction or recurring creator-authored visual motif;
- shape language;
- restrained accent association;
- characteristic but non-psychological posture/movement grammar;
- creator-supplied reference features;
- other persistent authored cues.

No single candidate family is mandatory, and color alone is never sufficient.

### CR-2 — Human specificity

A Character must read as a particular person, not as:

- generic avatar;
- provider/model badge;
- abstract node;
- profile record;
- interchangeable game token.

Specificity does not require photorealism.

A reduced or abstract representation may pass if distinct Characters remain reliably differentiable and relationally meaningful.

### CR-3 — Relational participation

The representation must be able to participate in composition so that relationship can be expressed through legitimate visual structure such as:

- orientation;
- proximity;
- scale;
- overlap;
- negative space;
- grouping;
- interruption;
- recurrence;
- attention placement when attention is explicitly represented by authority rather than inferred from anatomy.

The Character must remain an individual while participating in the shared field.

Required law:

> **Interaction may reorganize the composition without erasing individual identity.**

### CR-4 — State-channel independence

The Character's identity representation must not absorb semantic states that belong to separate system axes.

These must remain independently representable:

```text
Character identity
Presentation Perspective
Creator Posture
Presence
Current Opportunity / salience
Obligation (normally false / not implied)
Performance lifecycle
Causal-effect status
Technical capability
```

Example:

`B is my bounded perspective` and `C currently has opportunity` must remain simultaneously legible without recoloring either person's entire identity into a mode.

Required law:

> **State decorates or contextualizes identity; state does not rewrite identity.**

### CR-5 — Epistemic restraint

The representation must not claim private or unavailable information from visual appearance.

Do not infer as authoritative state:

- what someone believes;
- what someone knows;
- what someone noticed;
- what someone wants;
- trust level;
- fear, confidence, suspicion, affection or hostility;
- intention to act;
- agreement/disagreement;
- moral alignment;
- future response.

Facial expression, gaze, posture and gesture may contribute to artwork/performance portrayal, but **the interface cannot promote an interpretation of those cues into Production or Character authority unless the underlying authoritative state independently supports it.**

### CR-6 — Accessibility-equivalent identity

No essential Character distinction may depend solely on:

- face recognition;
- color;
- spatial position;
- animation;
- transparency;
- depth/material;
- subtle expression;
- hearing/voice.

The system must retain programmatic/textual identity and state equivalents.

A Character should remain identifiable under:

- high contrast;
- monochrome;
- reduced motion;
- text scaling;
- reduced transparency/material;
- image-disabled or image-unavailable conditions where appropriate;
- assistive technology traversal.

## 4. What a Character representation is NOT required to do

The representation contract does not require:

- a face;
- a full body;
- photorealism;
- animation;
- lip sync;
- emotion classification;
- gaze tracking;
- 3D rendering;
- generated imagery;
- a user-uploaded photo;
- one image per Character;
- one image per state;
- continuous re-rendering after every causal change;
- visible aging or physical mutation as the default expression of consequence;
- separate artwork for Watch vs Perform;
- separate artwork for Current Opportunity;
- any provider/model branding.

The Stage must remain useful when Character imagery is static.

## 5. Creator-authored imagery boundary

User-provided Character reference imagery remains a plausible future creation path, but it is **not yet a frozen feature**.

If later authorized, the architecture should preserve:

```text
Character authority
    !=
source image
    !=
generated derivative
    !=
current Stage representation
```

A source image would be creator input/reference, not the Character record itself.

Potential future paths remain open:

- upload one or more reference images;
- create a Character without imagery;
- AI-assisted generation from creator-authored description/reference;
- manual illustrated identity;
- import an existing creator-owned visual identity;
- mixed representation where different surfaces use different depths of depiction.

This proposal grants no privacy, consent, storage, model-training, likeness-generation, or image-processing implementation authority. Those require separate product/security/legal design when the feature is considered.

## 6. Representation-depth model — proposal, not ontology

For experimentation only, Character representation can be tested at several **visual depths** without making these storage enums:

### R0 — Textual identity only

Name + presence/state equivalents.

Purpose: prove the Stage still functions when imagery is absent.

### R1 — Reduced human invariant

Simple human form / silhouette / distinctive authored cues.

Purpose: test whether relational composition and identity survive without portrait realism.

### R2 — Expressive figurative identity

More specific face/body/garment/gesture detail while remaining stylized or illustrated.

Purpose: test human specificity and relational presence without relying on photography.

### R3 — Rich representational identity

Photographic, painterly, generated, or otherwise high-detail depiction.

Purpose: test maximum human immediacy and creator-authored/reference-driven possibilities.

These depths are a design-testing matrix only.

Do not implement a creator-facing `R0/R1/R2/R3` setting from this proposal.

## 7. Identity-invariant bundle requirement

A future representation system should prefer **redundancy**.

A Character should ideally remain recoverable through more than one independent cue, for example:

```text
name
+
shape/silhouette
+
one or more persistent authored visual cues
```

or:

```text
name
+
face/reference identity
+
garment/shape cue
```

or another equivalent bundle.

This reduces dependence on:

- one face crop;
- one color;
- one hairstyle;
- one camera angle;
- one artwork generation;
- one accessibility channel.

Earlier R0 artistic-language research supports the principle that identity can survive changes of crop, pose, viewpoint, scale and completeness through coherent perceptual invariants. The exact invariant set remains open.

---

## 8. Consequence / changed-present requirement

Causal change does not normally require the Character depiction itself to mutate.

The preferred order is:

```text
Production state changes
    ↓
relationship / opportunity / available action / current evidence changes
    ↓
Stage composition may reorganize
    ↓
Character identity remains stable
```

A Character may physically/visually change when the story legitimately changes their appearance, but that is a fictional consequence, not the default UI mechanism for signaling causal effect.

Required law:

> **Changed circumstance should not be confused with changed identity.**

---

## 9. Motion requirement

Motion may reinforce Character presence but cannot be necessary to identify or understand a Character.

Permitted future motion jobs may include:

- brief focus transition;
- local response to Current Opportunity changes;
- entering/leaving Scene;
- representation transition between valid visual depths;
- causal state reorganization.

Rejected by default:

- perpetual breathing/idle loops merely to make the product feel alive;
- continuous face animation;
- continuous graph/layout simulation;
- persistent GPU/NPU-driven decorative motion;
- motion-only indication of salience or perspective.

At rest, the representation system should be computationally quiescent.

## 10. AB1-derived information hierarchy around Characters

The convergence evidence supports this provisional hierarchy:

```text
1. specific people / relational field
2. current action / opportunity / bounded perspective
3. legitimate current evidence and authoritative facts
4. recent Performance when relevant
5. creator commands / advanced system material
```

Character representation belongs primarily to levels 1–2.

It should not become a permanent dossier container for levels 3–5.

This protects human presence from becoming database presentation.

If the Director approves this proposal, the smallest justified next visual experiment is **not** to design a final avatar system.

Working research name only:

`CRV-01 — Character Representation Viability`

Preserve:

- same P0 / S0 / A / B / C;
- Character-Bounded Watch;
- Current Opportunity = C;
- response not required;
- one already-effective current Production consequence;
- no private-mind inference;
- no Perform controls;
- no timeline / What Changed summary;
- no psychology metrics;
- no environmental narrative crutch;
- transcript minimized/progressive;
- editorial support quiet.

### CRV-01 comparison

Create three **independent** representations of the same current state:

1. **Reduced Human Invariant** — specific people without portrait realism;
2. **Expressive Figurative** — richer human depiction without photographic dependence;
3. **Rich Representational Control** — detailed human depiction as a control, without inheriting the prior AB1 room/cast surface.

Do not use one generated image as a visual reference for the next representation branch if doing so would freeze accidental surface.

### CRV-01 falsification questions

For every branch:

1. Can A/B/C remain individually recognizable?
2. Can B's perspective remain distinct from C's opportunity?
3. Can C become relationally salient without a graph or game-turn highlight?
4. Can the scene remain human rather than tokenized?
5. Can the changed present remain legible without changing Character identity?
6. Can the result survive monochrome / reduced detail conceptually?
7. Does the representation tempt the interface to infer private mind?
8. Does the representation require continuous rendering/motion to work?

One unrefined output per branch is enough for the first comparison.

Stop after cross-branch critique. No refinement chain is automatically authorized.
