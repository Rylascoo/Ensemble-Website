# KYMAEAN CSI-R1 — CONTINUOUS STAGE INTEGRATION RESULT

Status: DIRECTOR-ACCEPTED RESEARCH EVIDENCE / WHOLE-STAGE SEMANTIC INTEGRATION PASS / SURFACE-RESTRAINT PARTIAL FAIL / NO FINAL STAGE SURFACE SELECTED

Date: 2026-09-04

Phase: Kymaean App + Website Design Synthesis — after CSI-01 approval

Render ID: `7e082dbc-1522-46f3-9233-abf6e577f4ab`

## 0. Purpose

CSI-R1 tested whether the accepted Stage-facing contracts from SIPD -> CDT -> BCA -> AAS -> ARS could coexist in one human-first live Stage without collapsing perspective, posture, Current Opportunity, context, answer authority, bounded insufficiency, or same-Stage return into one generic dashboard.

The render reused the recurring controlled photoreal meeting baseline only to isolate integration behavior. Reuse does not grant surface inheritance rights.

## 1. Formal result

> **WHOLE-STAGE SEMANTIC INTEGRATION PASS / SURFACE-RESTRAINT PARTIAL FAIL**

The semantic architecture substantially coexists correctly. The dominant remaining errors come from accumulated surface/chrome rather than from the underlying authority model.

## 2. Strong passes

### 2.1 Perspective and posture separation

The Stage independently communicates:

```text
Presentation Perspective = Wren / B
Creator Posture = Watch
```

without the prior `Wren (You)` creator-embodiment ambiguity.

This materially validates the CSI correction:

> **Perspective identity must not be encoded as creator embodiment when Creator Posture remains Watch.**

Exact final labels remain open.

### 2.2 Current Opportunity independence

The Stage communicates:

```text
Current Opportunity = C
Response is not required.
```

Opening C-anchored context does not consume the opportunity, enter Perform, create obligation, assert intent/readiness, or change disclosure perspective.

### 2.3 Minimum bounded answer

The context answer is reduced to:

```text
Why is C currently relevant?

C currently has the opportunity.
The current context establishes that fact,
but not why C was selected.

Return to the scene
```

This preserves the validated BCA/AAS/ARS model:

- supported current truth first;
- exact causal boundary only because it is needed;
- no redundant Supporting Basis;
- no `About This Answer` lecture;
- no confidence taxonomy;
- no inaccessible-category explanation;
- no creator-facing engineering provenance;
- no speculative `Why?`/history route;
- one justified continuation/return.

### 2.4 Human-first continuity

The three people remain the first perceptual read even with context open. The same Production/Scene is visibly retained and context reads as inspection rather than causal mutation.

The accumulated transition remains viable:

```text
LIVE STAGE
-> meaningful anchor
-> one bounded question
-> one authoritative answer
-> exact boundary when needed
-> return
-> SAME LIVE STAGE
```

### 2.5 Representation remains non-authoritative

Rich facial expression, gaze, gesture, apparent speaking, and interpersonal orientation are present as portrayal only. The UI does not promote those visible cues into Character Observation, knowledge, belief, intent, or private psychology.

Patch 0014 authority remains intact.

## 3. Material surface-restraint failures

### 3.1 Context still reads as a conventional sidebar

The context surface remains a large independent white plane with its own portrait, heading, dividers, answer card, and navigation. Semantic continuity passes, but perceptual continuity remains partial.

The design still tends toward:

```text
living scene + software sidebar
```

rather than one integrated perceptual Stage.

### 3.2 Duplicate persistent Character roster is unproven

The Stage already depicts A/B/C prominently, yet a second permanent portrait-chip row repeats the same identities.

CSI-01 explicitly allowed the living field itself to carry identity continuity. CSI-R1 therefore provides evidence that a duplicate permanent roster may be unnecessary.

The semantic requirement for accessible Character identity remains. The portrait-chip row itself gains no persistence rights.

### 3.3 Ambiguous status dots fail

Small colored dots appear beside Character chips without an established semantic contract.

Possible user interpretations include readiness, online presence, turn state, attention, approval, model status, or availability. Because none is authoritative, state-looking decoration is unsafe.

> **State-like decoration requires defined semantics or removal.**

### 3.4 `PEOPLE / CONTEXT / PROGRESS` is a navigation regression

The render introduces permanent top-right destinations:

```text
PEOPLE | CONTEXT | PROGRESS
```

This conflicts with the accepted shell/navigation grammar:

> **Navigate between durable scopes; transition within one Production by following meaning.**

`Context` should emerge from the thing that raised the question rather than become a generic global silo. `Progress` is not an accepted Kymaean Production primitive and imports generic productivity-management semantics.

All three labels are quarantined as renderer-authored navigation.

### 3.5 Stage marketing copy fails

The render adds:

- `Different perspectives create a clearer tomorrow.`
- `REAL PEOPLE. RICHER POSSIBILITIES.`

These explain/market the product rather than carry current Production truth or creator task information.

The live Stage should not advertise Kymaean to a creator already inside the Production.

### 3.6 Product branding is over-weighted

A large `KYMAEAN` wordmark/logo occupies persistent Stage attention. App identity may exist at the application/scope layer, but CSI-R1 does not demonstrate that prominent product branding deserves the same weight as Production identity during ongoing creative work.

This remains an open shell-level question, not a selected correction.

### 3.7 Current Opportunity treatment is visually overbuilt

The semantic content is valid, but the large translucent card, circular token, repeated `C`, and state color risk making Opportunity resemble a gameplay turn indicator.

> **Opportunity = current salience/authority, not turn order.**

The semantic requirement survives; this exact card does not.

### 3.8 Dashboard perimeter accumulation

The human center is surrounded by:

- product wordmark;
- Production/Scene;
- Watch;
- search/menu/avatar controls;
- `PEOPLE / CONTEXT / PROGRESS`;
- duplicate Character roster;
- Current Opportunity card;
- marketing tagline;
- context sidebar.

The result is not yet a dashboard, but it demonstrates a **dashboard perimeter around a human center**. This is the primary whole-Stage reduction problem exposed by CSI-R1.
