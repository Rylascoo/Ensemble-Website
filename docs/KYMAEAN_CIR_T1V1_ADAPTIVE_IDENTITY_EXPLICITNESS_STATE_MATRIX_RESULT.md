## 3. Primary finding — explicitness is reversible presentation state

The eight cases establish that adaptive identity support is not a one-way onboarding sequence.

Valid behavior is bidirectional:

```text
ambiguity / task need rises
    -> identity becomes more explicit

ambiguity / task need falls
    -> identity may recede

ambiguity rises again
    -> identity becomes explicit again
```

The Character entity does not change anywhere in this sequence.

Promoted law:

> **Identity explicitness is reversible presentation state, not Character state.**

This preserves CIR-T1's anti-timer rule: elapsed time alone never earns recession while material ambiguity remains.

---

## 4. Selective explicitness result

The matrix does not require all Characters to carry the same visible identity weight simultaneously.

Example valid state:

```text
Riven = locally explicit because focused
Wren = explicitly named by Presentation Perspective
Vale = explicitly named by Current Opportunity
Watch = creator posture
```

These are separate reasons for explicitness.

Therefore:

> **Identity explicitness may be locally selective while Character identity remains globally stable.**

This avoids two opposite failures:

1. permanently labeling every Character merely because one Character needs clarification;
2. hiding a state-reference target because a local Stage label has receded.

## 5. State-reference result

CIR-T1V1 confirms the correction exposed by CIR-R1:

```text
Current Opportunity: Vale
```

is semantically preferable to requiring the creator to translate:

```text
Current Opportunity: C
C -> Vale
```

Research aliases remain useful in controlled documents/tests but do not earn product-facing identity authority.

The same principle applies to Perspective, task attribution and future dialogue attribution:

> **A product-facing state reference resolves directly to human-readable Character identity.**

## 6. Recession safety result

Name recession is allowed only when it removes redundancy rather than information.

A label may recede when:

- the Character remains unambiguously recoverable;
- a deterministic human-readable/programmatic identity path remains;
- no Perspective/Opportunity/focus/task target becomes unclear;
- narrow/image-limited/accessibility equivalence remains intact.

A label must reappear or another explicit identity channel must strengthen when those conditions no longer hold.

Promoted law:

> **Recession removes redundant presentation, never identity information.**

---

## 7. Identity-content boundary

Every matrix case remains solvable using identity itself.

No case requires adding:

- personality traits;
- profession/archetype summaries;
- psychology;
- intent/motivation;
- Observation/Knowledge/Belief claims;
- relationship judgments;
- trust/affinity scores;
- generated biography;
- product marketing copy.

Therefore CIR-R1's descriptor contamination was not merely stylistically excessive; it was unnecessary to the identity task.

Promoted result:

> **First-use memorability does not justify Character summarization.**

If future creator-authored Character information is exposed, it belongs to a separately bounded context/task contract and must use actual authority.

---

## 8. Epistemic restraint

Adaptive identity behavior never changes fictional authority.

Increasing or decreasing identity explicitness does not establish:

- who observed whom;
- what anyone knows;
- belief, suspicion or memory;
- emotion;
- intent;
- willingness to act;
- agreement/disagreement;
- social dominance.

Patch 0014 remains binding:

> **Visible portrayal != Observation / Knowledge / Belief / Intent authority.**

Opportunity may make Vale's identity explicit because the state references Vale; it may not make Vale's portrayal more psychologically assertive merely to dramatize the state.

## 9. Accessibility result

CIR-T1V1 validates the design contract only, not a final WinUI implementation.

A future implementation must ensure:

- stable accessible Character name/equivalent;
- deterministic visible-to-semantic Character association;
- separate announcement/recoverability for Perspective, Opportunity and focus when they reference different Characters;
- predictable traversal order;
- pointer/touch/keyboard/assistive equivalence;
- no hover-only identity;
- no accidental duplicate announcements from redundant visual + semantic identity elements;
- explicitness increases rather than decreases when visual channels become weaker.

Actual WinUI roles, `AutomationProperties`, high-contrast behavior and screen-reader execution remain implementation-stage validation.
