# KYMAEAN VISUAL SYSTEM GRAMMAR — PROPOSAL 01

Status: DIRECTOR PROPOSAL FOR REVIEW / NO PRODUCTION IMPLEMENTATION AUTHORIZED

Phase: Kymaean App + Website Design Synthesis — visual-system architecture after accepted grayscale continuous-workspace wireframe

## Purpose

Define the first coherent cross-product visual grammar for Kymaean without selecting a final palette, typeface, material treatment, portrait style, illustration medium, logo, wordmark, motion treatment, or exact WinUI control composition.

This proposal translates the accepted product/interaction structure into visual laws that can survive materially different surface languages.

## 1. Visual-system thesis

Candidate internal visual-system principle:

> **Human signal over system ornament.**

Meaning:

- people should usually carry the strongest identity signal;
- relationships should organize the visual field;
- software status should be explicit but quiet;
- consequence should alter hierarchy/organization where appropriate rather than merely add decorative effects;
- history should be recoverable from state comparison and causal structure rather than a permanent timeline motif;
- visual richness may be expressive, but the product should remain semantically complete when motion, transparency, color, and decorative imagery are removed.

This is a design-system principle, not a public tagline and not a selected aesthetic.

---

## 2. Primary hierarchy law — people before chrome

The accepted grayscale wireframe establishes a primary human field during live performance.

Visual design should strengthen, not reverse, that hierarchy.

Baseline ordering for present-performance focus:

```text
PEOPLE / HUMAN PRESENCE
        ↓
RELATIONSHIP + CURRENT ACTION
        ↓
RELEVANT CONSEQUENCE / PRESSURE
        ↓
SUPPORTING LANGUAGE / TRANSCRIPT
        ↓
CREATOR COMMANDS
        ↓
ADVANCED SYSTEM METADATA
```

This does not mean people must always be visually large or photorealistic.

It means the composition should still make sense if decorative UI chrome is removed.

Failure conditions:

- transcript becomes the dominant reading surface by default;
- card grids visually outrank the cast;
- provider/model telemetry competes with current dramatic meaning;
- decorative AI effects become the primary motion/contrast attractor;
- characters read as generic profile badges rather than persistent specific identities.

O0 continuity value:

> **The people are the scene.**

---

## 3. Relational geometry law

R0 established that relationship can function as visual structure through distance, orientation, overlap, negative space, interruption, occlusion, recurrence and attention.

The application may use this as an information-design resource.

Potential jobs for relational geometry:

- current attention/opportunity;
- interpersonal grouping/separation;
- selected relationship focus;
- changing participation in a Scene;
- comparison between prior and current relational organization;
- bounded visibility/access.

Constraint:

Relational geometry must not become a decorative force-directed graph requiring continuous physics or constant recomputation.

It should be deterministic, layout-driven, and capable of becoming completely still.

Accessibility requirement:

Spatial relation alone may never carry essential meaning. Equivalent text/structure must exist for keyboard, screen-reader, scaling, and narrow-layout use.

---

## 4. Identity system — invariant bundle, not permanent portrait

Kymaean needs persistent Character identity that can survive multiple visual contexts.

The system should therefore treat Character identity as a **bundle of coherent perceptual invariants**, not as one permanent headshot.

Candidate invariant classes for later exploration include:

- name / designed typographic signature;
- silhouette or body-form characteristics when figurative representation is used;
- characteristic line/shape construction;
- restrained personal accent association where accessible;
- recurring gesture/posture cues when motion/illustration supports them;
- consistent iconographic or compositional marker when appropriate;
- voice/language rhythm outside the purely visual layer.

No one invariant is mandatory.

The visual system should permit several representation depths:

```text
COMPACT IDENTITY
name + minimal mark

RELATIONAL IDENTITY
recognizable person in social field

FOCUSED IDENTITY
expanded Character representation/context

TRANSFORMED IDENTITY
same person under another crop, scale, perspective, abstraction or medium
```

The same Character must remain specific without requiring exact portrait repetition.

Explicit non-selection:

- no particle/constellation portrait system is selected;
- no photoreal portrait system is selected;
- no illustrated-avatar system is selected;
- no abstract-token system is selected.

Those remain surface explorations.

---

## 5. Typography — two registers, one hierarchy

O0 demonstrated that typography can participate in theatrical/literary identity rather than functioning only as neutral application text.

Windows-native readability still requires conventional interface hierarchy and robust scaling.

Proposal:

Use two conceptual typographic registers, without yet selecting typefaces.

### Register A — operational typography

Responsibilities:

- navigation;
- commands;
- status;
- metadata;
- forms;
- settings;
- accessibility-critical labeling.

Requirements:

- optimized for UI legibility;
- strong scaling behavior;
- readable at Windows text scaling;
- predictable numeral/punctuation behavior;
- language/localization compatibility appropriate to supported markets.

Windows feasibility reference:

Current Microsoft Windows guidance recommends Segoe UI Variable as the primary Windows UI type family and supports optical-size/weight variation. This is a compatibility reference, not a final Kymaean typeface selection.

### Register B — expressive narrative typography

Potential responsibilities:

- Character identity/name presentation;
- Scene titles or dramatic context;
- consequential state transitions;
- Archive/history emphasis;
- selected brand/wordmark relationships.

Constraint:

The expressive register must never make basic interaction dependent on ornamental typography.

The finished system may use one family capable of both jobs or two complementary families. That remains open.

---

## 6. Information hierarchy — fields before card accumulation

Kymaean should resist the default productivity-dashboard pattern of placing every concept inside a bordered card.

Preferred hierarchy model:

```text
CONTIGUOUS PRIMARY FIELD
        ↓
CONTEXTUAL LAYERS / INSPECTORS
        ↓
LOCAL GROUPING ONLY WHERE GROUPING HAS SEMANTIC VALUE
```

Cards remain valid when they communicate a real discrete unit, comparison, or actionable object.

They should not become the universal visual primitive.

Why:

- a card wall fragments the living Production into database objects;
- strong human/relational composition needs visual breathing room;
- continuous workspace continuity is easier to preserve when adjacent meaning can emerge without opening another tiled dashboard.

---

## 7. Shape language — semantic structure before branded geometry

No permanent corner radius, outline thickness, capsule language, aperture motif, K-derived geometry, threshold motif, or bespoke frame shape is selected.

Shape should initially serve four jobs:

1. containment when an object genuinely needs a boundary;
2. selection/focus;
3. authority/state distinction;
4. identity/relationship structure.

Avoid decorative geometry whose primary purpose is to make ordinary controls look proprietary.

Distinctiveness should come first from the interaction and human/relational system.

Bespoke geometry can be earned later where it creates semantic or brand value.

---

## 8. Color grammar — jobs before hues

No palette is selected.

Before choosing colors, define their jobs.

Candidate semantic jobs:

- interactive/action emphasis;
- current focus/selection;
- Character identity association where accessible;
- provisional/non-effective status;
- accepted/effective status;
- historical focus;
- warning/blocking capability state;
- positive/negative validation only where culturally and semantically appropriate.

Rules:

- no essential distinction is color-only;
- state meaning must remain readable in monochrome/high contrast;
- Character identity cannot depend solely on hue;
- the user's Windows theme/accent should be considered as part of the eventual system rather than treated as an enemy of brand consistency;
- dramatic emotional color may exist in artwork/brand surfaces without becoming the sole UI state code.

Current Microsoft Windows color guidance recommends using color sparingly and meaningfully, and recognizes user accent/theme personalization. Kymaean should be compatible with that expectation while retaining its own identity.

---

## 9. State language — explicit semantic evidence

Kymaean has unusually important state distinctions.

The visual system must make these understandable without requiring backend vocabulary.

Core classes:

```text
CURRENT
HISTORICAL
PROVISIONAL / NON-EFFECTIVE
ACCEPTED / EFFECTIVE
UNRESOLVED / STILL ACTIVE
BOUNDED PERSPECTIVE
CAPABILITY UNAVAILABLE
```

Each state should have a redundant semantic signature assembled from some combination of:

- wording;
- icon;
- shape/border treatment;
- placement;
- typographic emphasis;
- color;
- disclosure behavior.

No single cue carries the whole distinction.

Historical focus must not visually imply editable current state.

Technical capability failure must not resemble fictional dramatic consequence.

---

## 10. Consequence visualization — changed organization, not celebration effect

A consequence becomes visually meaningful when it changes what the creator understands about the present.

Prefer:

- changed ordering;
- changed relationship structure;
- a newly persistent current condition;
- altered affordance/action availability;
- changed prominence of a pressure or unresolved issue;
- before/after comparison when causal attribution needs it;
- traceable connection to the accepted event.

Avoid making every consequence a visual spectacle such as:

- particles;
- ripples;
- glowing trails;
- explosions of color;
- portal/rift imagery;
- permanent animated traces.

Those treatments may be explored artistically later, but they cannot be the semantic mechanism.

R0/TEO inheritance:

Minimal earlier/later comparison is a validated causal-observability tool when needed. It is not a mandatory split-panel visual identity.

---

## 11. History visualization — causality before chronology

History should primarily answer:

> **Why is this true now?**

Visual priority:

```text
CURRENT CONDITION
        ↑
CONSEQUENCE / RELATION
        ↑
RELEVANT EFFECTIVE EVENT
        ↑
PRIOR CONDITION
```

Chronological ordering remains available where useful but should not automatically become the dominant visual metaphor.

Possible visual structures later:

- focused causal chain;
- state comparison;
- event-to-consequence relation;
- unresolved continuation marker;
- selective chronological context.

No permanent timeline is selected.

---

## 12. Bounded perspective — subtractive visual grammar

Perspective should often be expressed by **what is no longer available**, not by decorating the interface with a Character theme.

When entering a bounded Character perspective:

- creator-only inspectors may close, redact, or disappear;
- privileged commands may disappear;
- accessible information may reorganize around what is available to that perspective;
- the same Production/Scene identity remains visible;
- identity/relationship continuity remains intact.

Avoid:

- changing the entire app into the Character's favorite color;
- applying a vignette/filter as the primary signal;
- leaving creator-only information visible but dimmed;
- implying certainty about private belief/intention that product authority does not support.

This is an information architecture transformation with visual consequences, not a cosmetic mode.

---

## 13. Material grammar — quiet foundation, earned depth

Windows-native materials are compatible with Kymaean but should remain infrastructure, not identity shorthand.

Candidate principle:

> **Material depth should clarify persistence, hierarchy, and transience.**

Potential mapping:

- persistent app/window foundation: restrained system-aligned base material or solid fallback;
- primary content: contiguous readable content layer;
- transient inspectors/flyouts: appropriate secondary depth;
- modal/blocking state: clear system-consistent separation.

Do not build the product's identity around glass/blur/translucency.

Current Microsoft guidance notes that Mica is designed as a performant long-lived window backdrop, while acrylic is suited to more transient surfaces and may fall back under battery saver, high contrast, disabled transparency, remote/unsupported conditions. Any Kymaean material choice must remain semantically complete under those fallbacks.

No final Mica/Acrylic/solid-surface composition is selected by this proposal.

---

## 14. Iconography — native verbs, bespoke domain meaning

Use standard Windows/Fluent iconography for conventional software verbs when a standard symbol is clear.

Examples of conventional jobs:

- Back;
- close;
- search;
- settings;
- more;
- play/pause where semantically appropriate;
- navigation disclosure.

Do not redraw ordinary platform verbs simply to make the app look branded.

Bespoke iconography may be justified for Kymaean-specific concepts where standard platform symbols are semantically inadequate.

Potential future domain concepts:

- causal consequence;
- unresolved pressure;
- bounded perspective;
- effective versus provisional performance;
- Character relationship/attention.

No bespoke domain icon set is selected yet.

---

## 15. Motion grammar — causal, local, optional

Motion may communicate:

- focus transfer;
- relationship reorganization;
- disclosure entering/leaving;
- transition from provisional to effective;
- return from historical inspection to the changed present.

Motion should generally be:

- user-triggered or state-triggered;
- brief;
- local to the affected relationship/state;
- interruptible where appropriate;
- semantically redundant with the final static state;
- absent when reduced-motion preferences require it.

Avoid:

- permanent ambient animation;
- continuous social-graph physics;
- decorative particles;
- perpetual background shader movement;
- idle character animation needed to make the interface understandable;
- continuous AI/NPU-driven visual reaction.

The still frame is the semantic authority; motion can clarify transition but must not own meaning.

---

## 16. Spatial rhythm — breathing room around human meaning

The visual system should reserve space around people/relationships rather than fill every available region with metadata.

Candidate rhythm principles:

- large uninterrupted regions are valid when they reinforce attention;
- density increases only when the creator deliberately asks for context/history/detail;
- inspectors should feel attached to a question/object rather than permanently docked administrative columns;
- command density should rise with creator posture/task and recede during Watch;
- narrow layouts preserve sequence and semantic order rather than miniature versions of wide layouts.

This gives the interface a dynamic density model:

```text
WATCH / EXPERIENCE
low chrome + high human field

INSPECT / UNDERSTAND
moderate contextual density

DIRECT / WRITE / CONFIGURE
higher purposeful density
```

Density changes with task; the product does not need one permanent information-density level.

---

## 17. Accessibility is part of the visual grammar

Every expressive decision must preserve:

- keyboard completion of the causal loop;
- visible focus;
- screen-reader-readable hierarchy;
- programmatic current/history status;
- programmatic active perspective;
- programmatic provisional/effective state;
- high-contrast survival;
- non-color state cues;
- scaling/reflow without essential spatial loss;
- reduced-motion equivalence;
- target sizes appropriate for pointer/touch where applicable.

Visual originality that disappears in high contrast or at 200% text scaling is not sufficient as the only semantic carrier.

---

## 18. ARM64 / battery visual budget

The visual system must be capable of becoming computationally quiet when the Production is not changing.

Preferred baseline:

- layout driven by state changes, not frame loops;
- static vector/icon/text composition where possible;
- no continuous graph solvers;
- no idle inference for decoration;
- no required live blur beyond system-managed material choices;
- no persistent video/canvas/WebGL-style surface in the retail app shell;
- no visual behavior that requires the NPU to remain active simply to make the UI feel alive.

The product should feel alive because **the Production changes**, not because the compositor is always moving.

---

## 19. Cross-product burden sharing

The app, website, wordmark, symbol, human-representation system, artwork, and motion do not need to express identical visual forms.

They need to share durable laws.

### App carries

- persistent human identity;
- relationship structure;
- disclosure/state clarity;
- causal continuity;
- interaction restraint.

### Website may carry more

- atmosphere;
- large-scale human artwork;
- narrative composition;
- broader symbolic/typographic expression;
- campaign-level visual worlds.

### Wordmark/symbol carry

- recognition and ownership;
- not the burden of explaining the full causal system.

Cross-product coherence therefore comes from shared principles rather than copied layouts or one universal motif.

## 20. Explicit anti-attractor boundary

This proposal does not select or imply inheritance rights for:

- dark luxury UI;
- black + gold/amber palette;
- pale-gold monumentality;
- portals/apertures/thresholds;
- giant walls/bridges/crossings;
- ruined or historical architecture;
- particle/constellation people;
- painterly beige figurative worlds;
- paper/collage ateliers;
- mystical libraries;
- causal diagrams as brand language;
- card-wall dashboards;
- permanent timeline interfaces;
- glassmorphism as identity;
- AI glow/gradient shorthand;
- generic sci-fi/Copilot visual language.

Any future experiment may independently rediscover a historical property only if it is re-earned from current product truth and visual-system laws.

## 22. First visual exploration matrix after approval

If this grammar is approved, do not immediately style the entire application.

The smallest justified next experiment is to apply the **same accepted grayscale wireframe state** to several deliberately different visual grammars while preserving all laws above.

Recommended first matrix:

### VSG-A — Human Editorial / Typographic

Test whether strong identity, editorial scale, typography and human presence can carry Kymaean with minimal ornamental geometry.

### VSG-B — Relational Field / Abstract Human

Test whether persistent identity and relationship can dominate through restrained abstract/invariant human representation without becoming anonymous tokens or diagrams.

### VSG-C — Material / Living Record

Test whether state/history/consequence can gain tactile or layered visual character without falling into parchment, antiquarian, collage, rustic-craft or magical-library shorthand.

These are experiment descriptions, not selected directions.

The three studies should be visually unrelated enough that success demonstrates the grammar survives surface replacement.

No branch earns refinement rights merely by being the first or strongest initial result.

## 23. Recursive audit

Audit order:

`product truth -> authority -> scope -> O0 experiential continuity -> R0 law continuity -> visual hierarchy -> typography -> human representation -> relational structure -> state semantics -> causality/history -> bounded perspective -> accessibility -> Windows-native feasibility -> ARM64/battery -> implementation simplicity -> cross-product coherence -> distinctiveness -> surface-inheritance check -> contradictions -> open decisions`

Material corrections required during audit:

1. rejected a single dark/light/palette recommendation because the clean-slate search has no incumbent palette;
2. replaced `portrait system` with an invariant-bundle identity model so the design does not freeze photorealistic or illustrated faces;
3. rejected cards as a universal component primitive;
4. separated color jobs from color selection;
5. made consequence visualization structural before decorative;
6. made bounded perspective primarily subtractive/disclosure-driven rather than theme-driven;
7. constrained motion to local causal transitions with static equivalence;
8. prevented Mica/Acrylic from becoming brand identity and required semantic fallback to solid/high-contrast states;
9. separated standard Windows software verbs from future bespoke Kymaean domain iconography;
10. made density task-responsive rather than a fixed dense/airy aesthetic;
11. added explicit anti-attractor boundaries without turning them into the positive creative premise;
12. preserved several deliberately unrelated visual-exploration branches rather than converging on one surface before evidence exists.

After correction and restart, the final complete pass found no material correction or worthwhile improvement within this proposal's scope.
