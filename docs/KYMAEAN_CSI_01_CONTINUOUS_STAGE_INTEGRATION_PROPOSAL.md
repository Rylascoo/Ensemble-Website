## 1. Governing synthesis

The Stage is not a container into which every valid system concept must be visibly placed.

The integrated law is:

> **The Stage presents the living Production first; system authority remains recoverable at the smallest level required for truthful understanding and action.**

This combines:

- `Human signal over system ornament.`
- `Stable Production, fluid focus.`
- `Importance does not imply permanence.`
- `Question-bounded, not schema-complete.`
- `Context inspection must not itself change the world being inspected.`
- `Representation can depict; authority must establish.`
- `Insufficient authority is an answer state, not an invitation to hallucinate.`
- `Trust signaling should be semantic before it is decorative.`

CSI adds one integration law:

> **Trust machinery should govern behavior more strongly than it occupies the interface.**

## 2. Default Stage semantic budget

The closed/default live Stage should contain only what must remain continuously recoverable.

### 2.1 Primary field

The first perceptual and semantic read remains:

```text
PEOPLE
-> RELATIONSHIP / CURRENT HUMAN SITUATION
-> MATERIAL CURRENT POSSIBILITY / CONSEQUENCE
```

Character identity must remain specific and accessible, but a separate permanent roster is not required if the living field itself carries sufficient identity continuity.

### 2.2 Quiet continuity anchors

Production and active Scene remain recoverable without becoming decorative headings.

Presentation Perspective and Creator Posture remain independently recoverable **when their distinction materially affects disclosure or agency**.

They do not need equal visual weight with the human field.

### 2.3 Current Opportunity

Current Opportunity remains visible/ambient only while materially active.

Required semantics:

```text
Current Opportunity = C
!=
C must respond
!=
C intends to act
!=
C is known to be ready
```

The relational field may carry salience, while explicit opportunity truth clarifies authority when necessary.

### 2.4 Default absences

The closed Stage does not require permanent:

- transcript;
- evidence taxonomy;
- Character dossier;
- contextual answer panel;
- causal-history timeline;
- `About this answer` disclosure explanation;
- provider/model/NPU telemetry;
- universal command ribbon;
- generic AI composer;
- confidence/truth-status system.

## 3. Perspective and posture integration

Presentation Perspective controls disclosure.

Creator Posture controls creator agency.

They remain orthogonal:

```text
Character B + Watch
= B-bounded disclosure, no B portrayal agency

Character B + Perform
= same disclosure authority, creator may portray B
```

CSI correction from ARS-R1:

> **Perspective identity must not be encoded as creator embodiment when posture remains Watch.**

Therefore a label such as `B Wren (You)` must not be treated as the default semantic solution for Character-bounded Watch.

Exact final labels remain open, but the surface must make these independently recoverable when necessary:

- whose perspective constrains disclosure;
- what creator posture is active.

No final `Perspective: Wren`, `Viewing as Wren`, or equivalent wording is selected by this proposal.

## 4. Context invocation within the whole Stage

Context remains user-driven by meaning.

Preferred flow:

```text
LIVE STAGE
-> creator follows one meaningful current anchor
-> ONE bounded contextual question
-> ONE primary contextual answer surface
-> dismiss / return
-> SAME LIVE STAGE
```

Opening context must preserve unless independently changed by Product authority:

- Production;
- Scene;
- Character identities;
- Presentation Perspective;
- Creator Posture;
- Current Opportunity;
- current authoritative Production truth.

The context surface is subordinate to the Stage, even when it temporarily carries focused information.

---

## 5. Integrated answer budget

When a contextual question is open, CSI adopts the minimum ARS-R1 form:

```text
question

supported answer

exact boundary — only if needed

one justified continuation
or return
```

### 5.1 Supporting basis

Supporting basis is optional.

It appears only when it adds distinct authoritative information necessary to understand or safely use the answer.

It must not repeat the answer because the layout expects a basis section.

### 5.2 Scope cue

Perspective/temporal scope appears only when omission would create ambiguity.

Scope language does not itself assert Character knowledge.

### 5.3 Bounded insufficiency

If authority cannot support the requested proposition:

- state the strongest supported truth first when one exists;
- state the exact boundary second;
- do not express deterministic insufficiency as low confidence;
- do not falsely negate the fiction;
- do not infer from visual portrayal;
- do not expose inaccessible categories merely to explain why they are absent.

### 5.4 Next route

Offer one next route only when it follows the meaning of the answer and is authoritatively satisfiable.

If no deeper supported route exists, return to the Scene is sufficient.

## 6. Invisible-authority principle

CSI deliberately rejects turning epistemic rigor into permanent explanatory chrome.

The following architecture should primarily govern **what the product does**, not become standing UI content:

- Access before Context;
- state-hash association;
- source-lane routing;
- claim-specific sufficiency;
- no inferred Observation;
- no unsupported causal `because`;
- no unsupported historical route;
- bounded insufficiency.

Creator-facing interface should expose these mechanisms only where a concrete task requires explanation.

Required law:

> **Authority precision is foundational behavior, not a dashboard aesthetic.**

## 7. Character-bounded Stage composition

Character-bounded perspective remains the strictest whole-Stage test.

The Stage should feel complete through subtraction.

Required sequence:

1. derive/obey active disclosure authority;
2. render the human field without promoting portrayal to epistemic truth;
3. expose only legitimately available current authoritative material;
4. preserve perspective and posture independently;
5. preserve Current Opportunity independently;
6. disclose deeper context only when invoked;
7. omit privileged material rather than showing locked/ghosted categories.

Patch 0014 remains authoritative:

- co-presence does not establish Observation;
- gaze/posture does not establish knowledge/intent;
- CharacterClaim disclosure/recall remains deferred;
- canonical recent Performance remains empty;
- other-owned subjective state remains denied.

## 8. Current versus historical integration

The live Stage remains CURRENT by default.

Current evidence answers:

> `What is true/available now?`

History answers:

> `Why is this true now?`

A historical affordance appears only when the requested explanation itself is authoritatively available.

History existence alone does not justify the route.

When history is entered later:

- historical locus becomes explicit;
- current Production remains retained;
- perspective limits remain active;
- return restores the prior Stage focus;
- navigation does not mutate Production truth.

CSI does not select a history surface or assert that Patch 0013/0014 retains a full creator-facing Director rationale.

---

## 9. Creator commands and posture

Commands follow task and posture rather than occupying permanent universal chrome.

### Watch

Default Watch requires no permanent text composer.

It may expose navigation/inspection affordances but no Character portrayal controls.

### Perform

Perform introduces the necessary bounded portrayal input because agency changed.

It does not increase disclosure privilege.

### Direct / Write

Their exact task surfaces remain open. CSI only preserves that command visibility follows the creator's current job rather than being permanently displayed.

## 10. Hierarchy / density requirements

The integrated Stage fails if the system layer becomes the strongest perceptual object by default.

Required hierarchy while closed:

```text
1. people / relationship / current human situation
2. materially relevant consequence / possibility / opportunity
3. quiet Production / Scene / perspective / posture continuity
4. contextual current answer only when invoked
5. deep history / diagnostics only on demand
```

While context is open, information may temporarily become the task focus but must not make the Stage feel replaced by a generic side-panel application.

One-context-at-a-time remains the default even on wide displays.

---

## 11. Accessibility

The integrated Stage must remain semantically coherent independent of:

- portrait recognition;
- spatial geometry;
- color;
- motion;
- simultaneous multi-column layout.

Required:

- Production/Scene identity programmatically recoverable;
- active perspective and posture announced when material;
- Current Opportunity exposed semantically without implying obligation;
- context invocation keyboard/screen-reader discoverable;
- context surface heading related to invoking anchor;
- predictable focus entry and return;
- bounded-answer limitation expressed in text/semantics, not color-only treatment;
- narrow layout can use `Stage -> Context -> Return` sequentially.

---

## 12. ARM64 / quiescence

CSI is intentionally compatible with low idle battery impact.

At rest the Stage does not require:

- continuous answer generation;
- speculative context pre-generation;
- background summarization;
- historical reconstruction;
- provider polling;
- relationship-graph physics;
- face/emotion analysis;
- persistent GPU/NPU activity.

Use already-authoritative deterministic local state whenever sufficient.

Future AI-required actions must degrade truthfully when unavailable; capability failure remains technical state, not fictional state.

CSI does not claim any current Windows AI/NPU implementation or runtime validation.
