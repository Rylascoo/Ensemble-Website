MANIFEST DISCIPLINE

The manifest separates:
- source-artboard dimensions;
- fixed method projection;
- fixed method instrumentation;
- one or more shared-surface volumes;
- one or more anonymous proxy volumes;
- actual proxy-to-proxy contact points;
- Director-side static cases;
- fail-closed sanitized-output policy;
- human-review status.

All normalized geometry values use at most four decimal places.

PROXY SOLID LAW

Every proxy is a union of deterministic convex polygon prisms extruded over z.

Proxy mass solids must:
- be closed prism solids;
- use uniform density;
- have interior-disjoint volume;
- meet only through shared boundaries when adjacent;
- carry at least one support-contact solid;
- generate support extent and COM from the same exact geometry later rendered into the sanitized view.

Interior overlap is rejected because double-counting overlapping mass would make the Director COM model differ from the physical solid represented by the transfer surface.

UNIFORM-DENSITY COM

For every proxy solid:

volume = polygon_area_xy * (z1 - z0)

solid_COM = (polygon_centroid_x, polygon_centroid_y, (z0 + z1)/2)

For a proxy composed of interior-disjoint solids:

proxy_COM = sum(volume_i * solid_COM_i) / sum(volume_i)

No alternate hidden stick-figure or hand-entered COM is accepted by this implementation.

SUPPORT GEOMETRY

Support geometry is derived only from proxy solids carrying:

support_contact: true

The Director report computes:
- support x interval;
- support z interval;
- support y level;
- COM;
- total normalized proxy volume.

Support geometry is therefore part of the same proxy solid model transferred visually.

ACTUAL CONTACT ADJACENCY

A body contact is not accepted as a symbolic relation.

For every contact:
- point_a and point_b must coincide exactly within implementation tolerance;
- that common 3D point must be contained by proxy A solid geometry;
- it must also be contained by proxy B solid geometry.

This prevents a hidden Director contact from being declared where the visible proxy solids remain separated.

STATIC CASES

The mechanism-neutral validator supports:

1. unsupported
- compares exact proxy COM x against exact support x interval;
- records signed support margin;
- classifies stable / unstable against a declared minimum margin.

2. supported_pair
- uses one actual horizontal-x contact;
- uses an explicit target center-of-pressure x inside the supported proxy footprint;
- solves the horizontal reaction required to close the supported proxy's 2D frontal-plane moment;
- applies the equal/opposite reaction to the counterparty;
- solves the counterparty support resultant;
- requires positive support margins according to the declared case.

These are construction-instrumentation calculations only. They create no post-render scoring rule and assume no literal final-human density model.

FROZEN ORTHOGRAPHIC PROJECTION

Candidate manifests cannot tune projection.

Frozen method constants:

mode = fixed_orthographic_oblique
depth_dx = 0.035
depth_dy = 0.025

For normalized source-plane point (x,y) and depth z:

screen_x = (x + z * depth_dx) * source_width
screen_y = (y - z * depth_dy) * source_height

This is linear / orthographic: no perspective division, focal length, depth-of-field, candidate-specific camera rotation or beauty framing exists.

FROZEN INSTRUMENTATION

Candidate manifests cannot tune instrumentation.

Frozen neutral values:

base_gray = 184

side_delta = -12

outline_width = 0.6

All geometry uses neutral grayscale only.

No hue coding, texture, material identity, specular design, atmospheric effect, cinematic lighting or candidate-specific tuning is available.

HUMAN-REVIEW BOUNDARY

The following cannot be legitimately reduced to numeric code:
- primary mannequin / sculpture / CAD / blockout / architectural-model reading;
- whether a candidate surface reads as recoverable changed-from-baseline physical geometry rather than self-sufficient designed form.

The manifest therefore contains explicit human-review states:

UNASSESSED / PASS / FAIL

for:
- maquette_leakage;
- surface_read.

transfer_eligible=true is invalid unless both are PASS.

The automated report distinguishes:
- automated_validation_pass;
- transfer_eligible.

A clean numerical result can therefore never silently authorize renderer transfer.
