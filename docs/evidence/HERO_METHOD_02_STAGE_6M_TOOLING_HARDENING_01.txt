CORRECTIONS

1. Projection and neutral instrumentation remain frozen method constants. Candidate manifests cannot tune them.

2. Proxy mass solids must be interior-disjoint. Positive-volume overlap is rejected so uniform-density COM cannot double-count material that the visible solid represents only once.

3. Declared proxy-to-proxy contact must be literal coincident 3D adjacency contained by both exact proxy solids. A hidden symbolic contact cannot substitute for visible physical adjacency.

4. Static moments use source-artboard physical scale: horizontal arms are multiplied by source width and vertical arms by source height. Normalized x/y are not treated as square physical coordinates.

5. Unsupported instability means the exact uniform-density COM lies outside the actual support interval. `minimum_margin` remains a pre-registered pass threshold; merely missing a preferred positive safety margin does not redefine a geometrically supported pose as unstable.

6. A `support_contact` solid must physically share a boundary segment with the one shared surface volume. Support extent is derived from that actual shared boundary, not from the whole nominal foot solid.

7. Proxy solids may not penetrate shared-surface solids.

8. Distinct proxies may meet at shared boundaries/contact but may not interpenetrate by positive volume.

9. Stage 6M uses exactly one shared physical surface volume. Its convex prism decomposition must be interior-disjoint and boundary-connected.

10. Each proxy's convex prism decomposition must itself be boundary-connected, preventing disconnected mass components from silently participating in COM/support calculations.

11. The internal base generator is not a canonical executable path. The public entrypoint requires the hardening layer. The base snapshot used by that layer is stored only as compressed, encoded, inert data split across exactly five files whose contents begin with an intentionally non-Python sentinel. The loader rejects missing or extra parts and verifies that the decoded snapshot has pinned Git-blob identity `fb3f367a4064129c1421c2008c7f4622e85bcc14` before executing it internally. Direct execution of either the loader or any source-data part is required to fail, and hosted CI tests both bypass paths.

The original first implementation remains preserved by repository history at blob `c99046240b0aa053ad8efa0de287d13cde8305b4`; the internal split-core snapshot is not claimed to be byte-identical to that historical blob because it already contains intermediate statics corrections made during recursive hardening.

The source-data encoding correction was added after the first hardened hosted run passed: recursive audit noticed that Python will execute a plain `.txt` containing Python source. That run is therefore intermediate evidence, not final approval evidence.
