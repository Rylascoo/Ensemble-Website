# KYMAEAN CDT-01 — CONTEXT DISCLOSURE TRANSITION PROPOSAL

Status: DIRECTOR PROPOSAL FOR REVIEW / NON-RENDER INTERACTION CONTRACT / NO FINAL CONTEXT SURFACE OR IMPLEMENTATION SELECTED

Phase: Kymaean App + Website Design Synthesis — after SIPD-V1 live Stage presence validation

## 0. Purpose

Define how the creator intentionally reveals deeper contextual information from the live Stage and then returns without breaking the sense of one continuous Production.

CDT-01 does not redesign the Stage or shell. It specializes the already accepted laws:

> **Stable Production, fluid focus.**

> **Importance does not imply permanence.**

> **Bounded disclosure is subtractive.**

> **Back/navigation does not mutate Production truth.**

This proposal does not select final panel geometry, animation, WinUI control, context labels, Character Context taxonomy, history UX, transcript architecture, or production implementation.

## 1. Design question

SIPD-V1 demonstrated that the closed/default Stage can remain coherent with very little permanent interface.

The next question is:

> **How can the creator reveal deeper truth without transforming the living Production into a dashboard?**

The transition must preserve:

- the same Production;
- the same Scene;
- the same Characters;
- the same Presentation Perspective;
- the same creator posture;
- the same Current Opportunity unless Product state itself changes;
- the same current/historical locus unless the user deliberately enters history;
- the creator's ability to return to the exact current meaning they came from.

---

## 2. Core transition law

The preferred disclosure transition is:

```text
LIVE STAGE
    ↓ creator follows a meaningful current anchor
CONTEXTUAL DISCLOSURE
    ↓ dismiss / Back / return
SAME LIVE STAGE
```

Opening or closing contextual disclosure is **navigation/session state**, not Production authority.

Required law:

> **Context inspection must not itself change the world being inspected.**

---

## 3. Meaningful invocation anchors

Context should normally open from a current element whose meaning the creator is following.

Valid anchor classes include:

- Character;
- Current Opportunity;
- current authoritative fact;
- current condition/pressure;
- current accepted/effective consequence;
- visible statement/action where the applicable authority makes it inspectable;
- capability limitation when the requested task is blocked.

Avoid a generic permanent `context dashboard` command as the primary model.

Preferred principle:

> **Follow meaning from the thing that raised the question.**

This preserves semantic continuity and gives the disclosure surface a clear relationship to the Stage.

---

## 4. Disclosure-state invariants

When contextual disclosure opens, the following remain invariant unless the creator explicitly changes them through another authorized action:

```text
Production identity
Scene identity
Character identity
Presentation Perspective
Creator Posture
Current Opportunity
current authoritative Production truth
```

Opening context must not:

- consume Current Opportunity;
- move opportunity to another Character;
- enter Perform;
- grant Character agency;
- reveal a more privileged perspective;
- create a Performance;
- create causal history;
- alter StateHash merely because UI state changed;
- infer observation or private mind.

---

## 5. Character-bounded disclosure contract

Character-bounded perspective is the strictest CDT test.

Before rendering any contextual content:

1. preserve the active Character-bounded Presentation Perspective;
2. apply/obey the same Access-before-Context authority boundary;
3. show only information legitimately available under that projection;
4. do not reveal inaccessible categories through disabled/locked placeholders;
5. do not infer observation from co-presence, dialogue visibility, nomination, relationship, SceneState, or causal adjacency;
6. do not convert gaze/posture into knowledge, intent, trust, confidence, skepticism or other private state.

Required principle:

> **Opening context may reveal more detail, but it must not reveal more privilege.**

---

## 6. Context surface responsibilities

A contextual disclosure surface may answer a narrow question such as:

- What is available to B about this current situation?
- What current fact makes this opportunity relevant?
- What condition is operative now?
- What evidence is legitimately available for this selected item?
- Why is this current state true now? — when deliberately entering causal trace/history.

It should not automatically dump:

- every Character field;
- every relationship;
- every evidence class;
- the full transcript;
- full causal history;
- provider/model telemetry;
- private categories unavailable to the perspective;
- unrelated creator-only information.

The content surface is therefore **question-bounded**, not schema-complete.

---

## 7. One-context-at-a-time default

Wide displays do not authorize unrestricted panel accumulation.

Default rule:

> **One active contextual question, one primary disclosure surface.**

A deeper disclosure may replace, drill into, or temporarily extend the current context, but should preserve a clear return path.

Avoid:

- evidence panel + Character dossier + transcript + history panel simultaneously;
- nested permanent sidebars;
- multiple competing inspectors merely because screen width permits them.

---

## 8. Stage continuity while context is open

On wide/medium layouts, the live Stage should remain perceptually primary or clearly retained behind/alongside the contextual surface.

The contextual surface may occupy adjacent space, overlay part of the Stage, or temporarily compress the Stage depending on final layout, but it should not make the user feel they entered a separate product.

On narrow layouts, sequential focus is acceptable:

```text
Stage
-> Context
-> Return to Stage
```

The semantic continuity is more important than simultaneous visibility.

---

## 9. Return / dismissal contract

Closing context must restore continuity predictably.

Required:

- return keyboard focus to the invoking anchor or a meaningful successor;
- preserve scroll/selection where feasible;
- preserve Production and Scene;
- preserve Presentation Perspective;
- preserve Watch/Direct/Perform/Write posture unless explicitly changed;
- preserve Current Opportunity unless Production state changed independently;
- restore the same current Stage rather than a generic root;
- keep a discoverable path to reopen the context.

Back means navigation history, not undo/revert/retcon.

Required principle:

> **Disclosure opens a question; dismissal closes the question, not the world.**

---

## 10. Current context versus causal trace

CDT must distinguish two disclosure routes.

### 10.1 Current-context expansion

Purpose:

- explain what is legitimately available **now** about a selected current item.

Temporal locus remains CURRENT.

### 10.2 Causal-trace/history expansion

Purpose:

- answer `Why is this true now?` by following current state into relevant effective history.

When entering this route:

- HISTORICAL locus becomes explicit;
- current Production remains retained;
- the selected current anchor remains the origin of the trace;
- perspective/disclosure limits remain active;
- return restores the prior current focus;
- inspection never mutates current authority.

TEO-style earlier/later comparison may appear inside causal trace when useful, but not as mandatory Stage structure.

---

## 11. Watch / Perform boundary during context disclosure

Opening context while Watch is active must remain Watch.

Do not expose:

- `Speak as B`;
- `Act as B`;
- Character performance composer;
- Character action menu;
- any implication that reading context grants portrayal agency.

If the creator explicitly enters Perform, that is a separate posture transition.

Conversely, while Perform is active, opening contextual detail must not expose creator-only information beyond the same Character disclosure authority.

Perspective controls disclosure; posture controls agency.

---

## 12. Opportunity continuity

Current Opportunity is independent of contextual disclosure.

Required:

```text
open context
!= consume opportunity

close context
!= restore opportunity

inspect C
!= assign opportunity to C
```

Opportunity changes only because Production/Director authority changes it, not because an inspector opened.

If the currently salient Character is also the context anchor, the UI may preserve that relationship visually, but must not imply obligation or intent.

---

## 13. Automatic versus user-triggered disclosure

Preferred default:

> **Context expands because the creator asks/follows meaning.**

Automatic disclosure is justified only when omission would create material ambiguity about:

- perspective;
- authority/effect;
- historical/current locus;
- blocked capability;
- safety/correctness of the immediately available action.

Even then, surface only the smallest corrective information.

Do not auto-open full context because:

- a Character begins speaking;
- Current Opportunity changes;
- the renderer detects a face/expression;
- a relationship is visually salient;
- the model considers something `interesting`.

---

## 14. Accessibility and focus contract

Progressive disclosure must be as coherent without spatial vision or animation as with it.

Required:

- invoking element has an accessible name and context action;
- opened surface has a semantic heading describing its relation to the anchor;
- active Presentation Perspective remains announced where relevant;
- focus moves deliberately into the disclosure surface;
- closing returns focus predictably;
- reading order does not depend on overlay geometry;
- context availability is discoverable by keyboard/screen reader;
- current versus historical locus is semantic, not color-only;
- reduced-motion mode preserves the same state transition meaning;
- high contrast/material fallback retains separation and focus.

No essential transition meaning may depend on animation alone.

---

## 15. Motion contract

Motion is optional reinforcement only.

If used, it should be:

- user-triggered;
- local;
- brief;
- interruptible where appropriate;
- semantically redundant with the final state;
- absent/reduced under reduced-motion preference.

Avoid:

- cinematic camera moves;
- persistent blur/zoom effects;
- animated graph expansion;
- decorative particle trails;
- motion that implies causal state change when only navigation state changed.

---

## 16. ARM64 / quiescence contract

CDT is intentionally compatible with near-zero idle work.

Context disclosure should be driven by existing local authoritative state and user interaction wherever possible.

Do not require:

- background summarization merely to keep panels ready;
- continuous provider polling;
- idle model inference;
- face/emotion analysis;
- relationship graph recomputation for decoration;
- persistent GPU/NPU activity;
- speculative pre-generation of context that the creator may never open.

If a future context request legitimately requires inference, capability gating and deterministic fallback must remain explicit and truthful.

---

## 17. Capability degradation

If a contextual surface can be populated from existing deterministic local state, it should remain available even when generative AI is unavailable.

If a requested deeper function requires unavailable capability:

- retain the Stage;
- retain already-authoritative context;
- explain the unavailable function truthfully;
- do not fabricate fictional detail;
- do not turn technical failure into Character behavior;
- do not change Production truth.

Capability state is technical state, not dramatic state.

---

## 18. Surface quarantine

CDT selects no visual treatment.

No inheritance rights for:

- exact SIPD photoreal meeting-room surface;
- exact right-side inspector geometry;
- white/cream palette;
- rounded-card styling;
- exact icons;
- portrait-chip row;
- current opportunity card shape;
- slide-over versus docked panel behavior;
- exact animation;
- generic productivity/SaaS shell styling.

The experiment is about semantic transition, not appearance.

---

## 19. Controlled validation proposal

If CDT-01 is approved, the smallest justified visual test is:

`CDT-V1 — Bounded Context Invocation`

Use the existing SIPD-V1B closed/default Stage as the **controlled semantic/visual baseline**, because this test is specifically about transition continuity rather than surface divergence.

Generate exactly one context-open state from that baseline.

Required invariants:

- same P0 / S0 / A / B / C;
- same Character-Bounded Watch;
- same Current Opportunity C;
- response not required;
- same current Production state;
- no Perform controls;
- no full transcript;
- no causal-history timeline;
- no diagnostics;
- no environmental narrative text added to explain state;
- no private-mind inference;
- no inaccessible-category placeholders.

The context surface must be invoked from one meaningful current anchor and answer one bounded question only.

The existing closed Stage + one new open-context state are sufficient for comparison. A third `closed again` render is unnecessary if the transition contract clearly requires exact restoration of the baseline Stage.

Falsification questions:

1. Does the Stage still feel primary while context is open?
2. Is the context clearly related to its invoking anchor?
3. Did disclosure detail increase without privilege increasing?
4. Did Watch remain Watch?
5. Did Current Opportunity remain unchanged/non-obligatory?
6. Did the context avoid schema-dump/dashboard behavior?
7. Can the surface close and conceptually restore the exact baseline Stage?
8. Does the interaction remain understandable without motion?
9. Does the context survive narrow/sequential layout conceptually?
10. Does any text infer observation/private psychology beyond authority?

Stop after the first unrefined open-context state and critique. No automatic correction chain.

---

## 20. Recursive audit

Audit order:

`Director authorization -> SIPD closed-stage result -> existing shell/navigation grammar -> invocation anchor -> disclosure invariants -> Character-bounded access -> Watch/Perform orthogonality -> opportunity continuity -> current/history boundary -> focus/Back semantics -> accessibility -> capability degradation -> ARM64 quiescence -> surface quarantine -> falsification sufficiency -> scope`

Material corrections made during construction:

1. defined context opening as navigation/session state rather than Production mutation;
2. required meaningful anchor-based invocation rather than a generic permanent context dashboard;
3. prohibited privilege increase when disclosure detail increases;
4. prohibited inaccessible-category placeholders in Character-bounded context;
5. separated current-context expansion from causal-history expansion;
6. preserved Watch posture while context opens;
7. preserved Current Opportunity independently from inspection;
8. established one-context-at-a-time as the default to prevent dashboard accumulation;
9. made exact focus restoration part of the transition contract;
10. made motion optional and semantically redundant;
11. rejected speculative/background inference as a prerequisite for progressive disclosure;
12. reused SIPD-V1B as the validation baseline to isolate transition rather than starting another surface exploration.

After each material correction, audit restarted from Director authorization and current product authority.

Final complete pass:

> **PASS — no remaining material disclosure-authority leak, navigation/causality conflation, posture/perspective conflation, opportunity coupling, accessibility/focus defect, quiescence concern, surface-inheritance leak, or worthwhile correction inside CDT-01 proposal scope.**
