CIR governing laws:

> **State may reference a Character; state does not define who that Character is.**

> **A Character must remain identifiable when any one non-essential visual cue disappears.**

> **Identity must always be recoverable; identity labels do not need to be continuously visible.**

> **Opportunity may point to a Character; it must not reduce the Character to a turn token.**

## 3. Primary finding — adaptive explicitness

The seven cases expose one common behavior:

> **As visual certainty decreases, semantic identity explicitness increases.**

This does not require a permanent roster.

A full rich Stage may permit identity to be carried primarily by the living representation plus an available textual/programmatic identity channel.

A reduced or narrow Stage may need names to become more directly visible around the current focus or anchor.

An image-unavailable or assistive traversal requires textual/programmatic identity to become primary.

The identity truth does not change as the presentation channel changes.

Candidate promoted law:

> **Identity explicitness should adapt to ambiguity; Character identity itself must remain stable.**

---

## 4. Roster-removal result

No CIR-V1 condition requires a permanent duplicate portrait roster.

That conclusion is narrower than saying a people/Character inspection surface can never exist.

CIR-V1 establishes only:

- the default live Stage does not need a second persistent representation of every Character merely to preserve identity;
- accessibility does not justify duplicating visual portraits if one semantic Character representation already exposes the correct accessible identity;
- narrow or image-unavailable modes may become more textually explicit without recreating a permanent avatar rail.

Required distinction:

```text
identity recoverability
!=
duplicate visual roster
```

## 5. Perspective / Opportunity / focus reference integrity

The most demanding state combination is:

```text
Character identities:
Riven / Wren / Vale

Creator Posture:
Watch

Presentation Perspective:
Wren

Current Opportunity:
Vale

Current focus / selection:
Riven
```

CIR-V1 confirms that these can remain conceptually orthogonal if every state references the same stable Character identity rather than becoming an alternate identity system.

Therefore:

> **A state reference must resolve to Character identity; it must not manufacture Character identity.**

Consequences:

- Perspective may say or semantically expose `Wren`, but does not make Wren `(You)`;
- Opportunity may expose `Vale`, but does not reduce Vale to `C` or a turn token;
- focus may expose `Riven`, but does not recolor/re-render Riven into a different identity;
- Watch remains creator agency/posture and is not attached to Wren as identity ownership.

---

## 6. Image-unavailable result

The image-unavailable case is the strongest falsification of portrait dependence.

The Stage may become visually poorer, but the product model remains intact if it still exposes:

- Character names/human-readable identities;
- current Scene participation;
- Perspective identity;
- Current Opportunity identity;
- current task attribution;
- accessible traversal and focus.

Optional fallback imagery may assist scanning but cannot become the sole identity source.

Promoted finding:

> **Character imagery enriches identity presentation; it is not the authority for who the Character is.**

---

## 7. Accessibility result

CIR-V1 validates the semantic requirement, not a final WinUI implementation.

A future implementation must ensure that a user relying on keyboard or assistive technology can recover the same Character identity that a sighted pointer user receives.

The design therefore cannot depend on:

- hover-only names;
- portrait recognition;
- color;
- precise spatial position;
- gesture;
- animation;
- simultaneous wide-screen composition.

The visual representation and accessible semantic element must also avoid accidental double-announcement when both represent the same Character.

Exact control roles, AutomationProperties, focus behavior and Windows implementation remain unselected and require implementation-stage validation.

---

## 8. Epistemic boundary

Nothing in CIR-V1 authorizes identity cues to become fictional state.

Stable identity cues must not encode or assert:

- knowledge;
- Observation;
- belief;
- memory;
- intention;
- willingness to act;
- emotion;
- trust;
- agreement/disagreement;
- social dominance.

Patch 0014 remains binding:

> **Visible portrayal != Observation / Knowledge / Belief / Intent authority.**

The matrix never requires gaze, facial recognition, emotion analysis or body-language inference to determine identity.

## 9. ARM64 / privacy / quiescence

All seven cases can be satisfied from deterministic local Character identity/state plus authored representation metadata.

No CIR-V1 condition requires:

- face recognition;
- biometric identity inference;
- embedding comparison;
- gaze/emotion analysis;
- camera access;
- background AI generation;
- continuous image regeneration;
- provider polling;
- persistent GPU/NPU activity.

At rest, identity mapping remains quiescent and changes only when authoritative Character/state/UI focus changes.

No Windows AI Foundry or NPU execution behavior is claimed.

## 11. Recursive audit

Audit order:

`Director authorization -> CIR-01 -> SPR-R1B -> Character Representation Requirements -> CRV-01 -> full Stage/no roster -> reduced detail -> narrow/sequential -> image-unavailable -> assistive traversal -> Perspective/Opportunity split -> independent focus/selection -> entity/name/state distinction -> single-cue-loss test -> accessibility equivalence -> epistemic restraint -> ARM64/privacy/quiescence -> surface quarantine -> scope -> anti-churn`

Material corrections incorporated during matrix audit:

1. did not treat a visually recognizable face as sufficient identity;
2. did not require permanent visible names in the full Stage;
3. increased textual/programmatic explicitness as visual certainty decreases;
4. did not restore a duplicate permanent portrait roster in narrow or assistive modes;
5. made image-unavailable operation a first-class identity test rather than an error-only fallback;
6. made state references resolve to human-readable Character identity rather than A/B/C tokens;
7. kept Perspective, Opportunity, selection and Posture simultaneously orthogonal;
8. kept focus styling separate from identity mutation;
9. avoided hover-only and pointer-only identity access;
10. preserved no-private-psychology/no-Observation inference;
11. preserved deterministic/quiescent identity mapping;
12. did not select a final visual medium or WinUI accessibility topology.

Final complete pass:

> **PASS — no remaining material roster-restoration requirement, identity/state conflation, accessibility contradiction, single-channel dependency, epistemic leak, quiescence concern, surface-selection leak, or worthwhile correction inside CIR-V1 matrix scope.**

## 13. Conclusion / next unresolved question

CIR-V1 answers the contract-level question positively:

> **Character identity can remain durably recoverable without a permanent roster if the system preserves a stable human-readable/programmatic identity channel, medium-appropriate redundant visual invariants, and adaptive semantic explicitness as visual certainty decreases.**

The smallest unresolved design question is now surface-level rather than ontology-level:

> **Can a no-roster live Stage make all present Characters discoverably identifiable at first use—while keeping people first, avoiding permanent nameplate clutter, and preserving independent Perspective, Opportunity and focus references?**

A later controlled visual experiment may test that question, but no render is authorized by CIR-V1 itself.
