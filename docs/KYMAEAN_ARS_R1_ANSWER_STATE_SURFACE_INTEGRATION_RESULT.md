## 2. Strong passes

### 2.1 Supported truth + exact boundary

The answer:

> `C currently has the opportunity.`
>
> `The current context establishes that fact, but not why C was selected.`

is a strong integrated realization of the ARS/AAS contract.

It correctly preserves:

```text
supported current fact
!=
unsupported causal explanation
```

It does not translate missing authority into low confidence, uncertainty, fictional negation, or a fabricated reason.

### 2.2 Semantic trust without visible status taxonomy

The surface does not require visible `SUPPORTED`, `VERIFIED`, `UNCERTAIN`, confidence percentages, or traffic-light truth states.

The answer remains understandable without color or iconography.

Promoted law:

> **Trust signaling should be semantic before it is decorative.**

### 2.3 No false `Why?` promise

The requested causal explanation is not established, and the surface does not offer `Why?`, `See why`, `Trace why`, or a history affordance that would promise an unavailable answer.

The only next path is return to the Scene.

This validates:

> **A route exists because the requested meaning can be authoritatively followed, not because more data or history exists somewhere.**

### 2.4 Continuous Stage retained

The same Production/Scene/human field remains visible while context is open.

Character-Bounded Watch remains Watch. C remains Current Opportunity. `Response is not required.` remains explicit. Opening the answer does not imply Production mutation.

The cumulative interaction remains coherent:

```text
LIVE STAGE
-> meaningful current anchor
-> bounded question
-> supported answer
-> exact authority boundary when needed
-> return to SAME LIVE STAGE
```

## 3. Surface-restraint failures

### 3.1 Trust machinery became too visible

The panel simultaneously exposes:

- `Context Answer`;
- perspective-availability explanation;
- `Your Question`;
- `Answer`;
- `Supporting Basis`;
- `About This Answer`;
- `Next Step`.

The actual useful semantic payload is much smaller.

Required correction:

> **Kymaean's authority system should create confidence through restraint, not through visible machinery explaining why it is trustworthy.**

### 3.2 `About This Answer` over-explains disclosure taxonomy

The text naming `private thoughts` and information from other perspectives teaches inaccessible categories rather than simply withholding them.

That conflicts with the subtractive Character-bounded law.

Default correction:

- omit inaccessible-category explanation;
- use only the smallest scope cue when the active perspective would otherwise be ambiguous.

### 3.3 Supporting basis must be earned

The rendered `Supporting Basis` repeats the answer by restating that C is the current opportunity holder.

The mechanism is valid, but the content is redundant.

Promoted rule:

> **A valid supporting-basis mechanism does not imply that every answer needs supporting basis.**

Supporting basis appears only when it adds distinct, necessary authoritative support.

### 3.4 Avoid creator-facing engineering provenance by default

`(Production state)` reads as implementation/provenance metadata rather than necessary creator-facing meaning.

Ordinary answers should present the supported truth. Deeper provenance, if later useful, must be a deliberate specialist route rather than default answer copy.

### 3.5 Decorative success semantics remain a risk

The green Answer treatment can be read as `green = verified truth` even though the semantic answer itself does not require that color.

No color, card tint, icon, or badge gains truth-status meaning from this experiment.

### 3.6 Context still competes with the human field

The high-contrast white panel, section dividers, icons, and text density carry substantial information contrast against the people.

The Stage remains retained, but human-first hierarchy is only a partial pass while context is open.

Future integrated Stage work must reduce contextual visual gravity rather than merely shrinking the human field around a conventional inspector.

## 4. Perspective / posture correction

The recurring label:

`B WREN (You)`

remains semantically ambiguous.

It can incorrectly imply any of:

- account identity;
- creator embodiment;
- active Character portrayal;
- Character ownership;
- merely viewing through B's bounded perspective.

Required law:

> **Presentation Perspective must not be encoded as creator embodiment when Creator Posture remains Watch.**

CSI-level follow-up should keep perspective and posture independently recoverable. Exact labels remain open; no final `Perspective: Wren` copy is selected by this result.

## 5. Portrayal / epistemic boundary

The rendered people strongly invite ordinary human inference from gaze, gesture, and apparent speech.

That is acceptable portrayal.

The answer correctly does not convert those visual cues into statements such as `B saw C speaking` or `B knows C is presenting terms`.

Patch 0014 therefore remains the governing boundary:

> **Representation can depict; authority must establish.**

## 6. Minimum integrated answer form

ARS-R1 supports the following default semantic form:

```text
question

supported current answer

exact boundary — only when necessary

one justified continuation
or return
```

Optional material must earn its presence:

- supporting basis only when it adds necessary distinct support;
- perspective/scope cue only when ambiguity would otherwise exist;
- historical route only when that exact explanation is authoritatively available;
- no general `About this answer` disclosure lecture;
- no generic `Ask anything` continuation;
- no engineering provenance label by default.
