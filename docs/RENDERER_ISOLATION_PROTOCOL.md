# Kymaean Renderer Isolation Protocol

Status: **ACTIVE PROJECT LAW FOR CLEAN-SLATE VISUAL GENERATION**

Purpose: separate persistent project intelligence from image-rendering context so Kymaean can preserve its complete creative memory without repeatedly contaminating new visual generations with historical surface vocabulary.

## Core principle

> **The director remembers everything. The canvas remembers nothing.**

Kymaean visual development uses two deliberately different contexts:

1. **Director Context** — persistent, project-only, historically informed.
2. **Renderer Context** — short-lived, outside the Ensemble project, intentionally history-blind.

The Director Context owns product truth, visual lineage, user reactions, critique history, Drive continuity, evaluation, and experiment design. The Renderer Context receives only a bounded concrete scene description and generates artwork without knowing it is part of Kymaean, Ensemble, a website, an app, AI software, or a visual-identity exercise.

## Current ChatGPT capability correction

A non-personalized Temporary Chat is **not the default renderer** because image generation may be unavailable in Temporary Chat in the user's current ChatGPT configuration. Do not require Temporary Chat merely for sterility.

The default Renderer Context is therefore a **new regular chat outside the Ensemble project**.

The Ensemble project should use **Project-only memory** when available. Under current ChatGPT project-memory behavior, project information remains available inside the project while project information is removed from memory used outside the project. This makes an ordinary non-project chat the practical rendering boundary while retaining image-generation capability.

For stronger isolation when needed, the user may temporarily disable account-level Memory and Custom Instructions before opening the renderer chat, generate the bounded experiment, and then restore those account settings afterward. Do not delete saved memories merely to run an experiment; the goal is to prevent their use during rendering, not destroy them.

Product settings and tool availability can change. Preserve the architectural intent rather than a particular UI label: **persistent informed Director; short-lived history-blind renderer with image generation available.**

## Why this protocol exists

Repeated visual-development chats, including fresh chats inside the Ensemble project, repeatedly collapsed toward related unapproved surface attractors: monumental/cinematic scale, thresholds and apertures, dark-luxury treatment, gold accents, portals, abstract symbolic figures, brand-board composition, explanatory collateral, and other previously discussed visual vocabulary.

The failure was not only insufficient art direction. The project had been asking one context to perform two incompatible jobs:

- remember all prior design history well enough to preserve continuity;
- forget that history well enough to invent an independent visual surface.

A fresh chat inside the same project does not provide a sufficiently sterile rendering context. The solution is architectural separation rather than increasingly elaborate negative prompting.

## Director Context

The Director Context is the Ensemble/Kymaean website-brand project itself.

It may and should know:

- `Rylascoo/Ensemble-Website` current state and design law;
- `Rylascoo/Ensemble-Project` product truth and validation boundaries;
- Google Drive `Ensemble Project` visual masters and critique history;
- O0 and all later historical branches;
- historical favorites, failures, user reactions, and design judgments;
- prior generated artwork once the active experiment permits historical comparison;
- the complete evaluation framework and project vocabulary.

The Director Context must **not generate clean-slate artwork directly** unless the user explicitly chooses to run a controlled in-project comparison or abandons this isolation protocol for that experiment.

Its job is to formulate the human situation, causal structure, experiment boundary, and evaluation criteria, then emit a Sterile Render Packet.

## Renderer Context

For normal R0 clean-slate visual generation, use a **new regular chat outside the Ensemble project**.

The Renderer Context should:

- have no project files;
- receive no Kymaean/Ensemble design documents;
- receive no historical Kymaean artwork;
- receive no project-chat continuity in its prompt;
- receive no visual-history blacklist;
- receive no previous renderer prompt unless the current experiment intentionally depends on it;
- have the shortest practical lifetime, normally one concept or a very small bounded attempt set.

For an orthogonal visual experiment, start a new Renderer Context rather than allowing the previous renderer chat to accumulate its own visual attractor.

**Creative intelligence persists. Rendering context expires.**

## Optional stronger-isolation settings

When an ordinary outside-project chat still shows evidence of unwanted personalization or historical influence:

1. keep the Ensemble project itself on Project-only memory;
2. temporarily disable account-level Memory before creating the renderer chat;
3. temporarily disable Custom Instructions before creating the renderer chat;
4. create the renderer as a new regular non-project chat;
5. paste only the Sterile Render Packet;
6. generate the artwork;
7. return the artwork to the Director Context;
8. restore the user's normal Memory and Custom Instructions settings.

Do not make this stronger-isolation sequence mandatory unless evidence shows it is needed. Project-only memory plus a new ordinary non-project chat is the default first test.

## Sterile Render Packet law

A Sterile Render Packet is the only material normally transferred from the Director Context into the Renderer Context.

It should describe **observable human circumstances**, not Kymaean's abstract design thesis.

Do not include, unless indispensable to a deliberate experiment:

- Kymaean;
- Ensemble;
- Human Causality, Living Consequence;
- AI;
- app;
- website;
- branding;
- visual identity;
- logo or wordmark language;
- historical branch names;
- design-critique terminology;
- previous artwork descriptions;
- negative lists of historical motifs.

Avoid asking the renderer to visualize abstractions such as causality, consequence, memory, persistent worlds, bounded perspective, or information asymmetry. Encode those ideas through concrete events, objects, relationships, actions, evidence, and unequal knowledge.

## Causal scene grammar

When useful, formulate experimental scenes through this concrete sequence:

**Prior human act -> physical/social evidence -> changed present affordance or constraint -> another person's response -> unequal understanding.**

This is a construction aid, not a mandatory composition or genre.

The originating act may involve care, generosity, affection, repair, refusal, theft, error, compromise, sabotage, promise, misunderstanding, accommodation, interruption, sacrifice, neglect, curiosity, or another specific human cause.

The goal is not to diagram causality. The goal is to create a situation in which causality is already true.

## Artwork-only execution contract

Unless a specific experiment intentionally studies typography or collateral, the Renderer Packet should request artwork as artwork.

Do not include:

- logos;
- wordmarks;
- marketing copy;
- explanatory captions;
- website or app UI;
- presentation boards;
- moodboards;
- comparison grids;
- palette swatches;
- experiment titles;
- branding panels.

If the renderer nevertheless produces branded collateral, classify the output as execution-failure evidence before evaluating its visual discoveries.

## First-pass causal gates

Before evaluating beauty, brand potential, palette, style, or production suitability, the Director Context asks:

1. **Person-removal test:** If the people disappeared, would the image lose its essential meaning?
2. **Evidence test:** Can we identify something that exists or has changed specifically because somebody previously did something?
3. **Changed-possibility test:** Does that prior action materially affect what another person can do now?
4. **Unequal-understanding test:** Can different people plausibly understand, know, or interpret the situation differently?

These are diagnostic gates, not a numeric score. A failure can still produce a transferable discovery, but visual polish cannot substitute for the missing causal condition.

## Full evaluation after causal gates

If the work survives the initial causal review, evaluate it using the existing R0 dimensions, including:

- emotional magnetism;
- human importance;
- identity specificity;
- relational complexity;
- consequence changing future possibility;
- bounded perspective;
- historical specificity;
- provenance/evidence;
- mystery;
- artistic integrity;
- distinctiveness;
- expandability;
- attractor risk;
- surprise.

Do not infer convergence from one successful image.

## Return path

After rendering:

1. bring the resulting artwork back into the Director Context;
2. evaluate it with full project intelligence;
3. preserve useful failure evidence as failure evidence;
4. extract transferable discoveries without granting surface inheritance rights;
5. record relevant user reaction and design judgment;
6. prepare the next Sterile Render Packet;
7. use a new Renderer Context when pursuing an orthogonal experiment.

At handoff/retirement, the existing visual archive protocol still governs Drive preservation, provenance, critique, and historical classification.

## Controlled contamination test

When diagnosis requires evidence, the project may deliberately run the same bounded scene under two conditions:

- **A — In-project render** with project context available;
- **B — Isolated render** in a new regular non-project chat using only the Sterile Render Packet.

Compare the outputs for recurrence of historical visual vocabulary, branding/collateral contamination, causal specificity, human importance, and novelty.

If necessary, repeat B with Memory and Custom Instructions temporarily disabled to distinguish project-context contamination from account-level personalization.

This is an explicit experiment, not the normal production workflow.

## Relationship to R0

This protocol strengthens, rather than replaces, R0 Visual Re-Foundation.

R0 still governs:

> **Preserve the lineage. Restart the search.**

Renderer Isolation defines how to make that principle operational when image generation itself is context-sensitive.

Historical inspiration remains available to the Director. It is withheld from the renderer unless a deliberate historical revival or comparison experiment requires it.

No historical surface becomes forbidden. No historical surface receives inheritance rights.

## Permanent rule

For clean-slate visual-world generation, **do not render inside the persistent Ensemble project by default**.

The Director designs the experiment. The isolated renderer makes the image. The Director interprets the result.
