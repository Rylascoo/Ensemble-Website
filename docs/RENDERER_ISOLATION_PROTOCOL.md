# Kymaean Renderer Isolation Protocol

Status: **ACTIVE PROJECT LAW FOR CLEAN-SLATE VISUAL GENERATION**

Updated: 2026-09-07

Purpose: separate persistent project intelligence from image-rendering context so Kymaean can preserve complete creative memory while reducing direct inheritance of historical surface vocabulary.

## 1. Core principle

> **The director remembers everything. The canvas remembers nothing.**

This is an operational architecture, not a claim that the image model has literally zero memory or zero learned priors.

Kymaean visual development uses two deliberately different contexts:

1. **Director Context** — persistent, project-based, historically informed.
2. **Renderer Context** — short-lived, outside the Ensemble project, intentionally deprived of project history.

The Director Context owns product truth, visual lineage, user reactions, critique history, Drive continuity, evaluation, experiment design, formal-grammar control, archival classification, and design-phase authority.

The Renderer receives only the bounded experiment packet needed for that render and should not need to know that the image belongs to Kymaean, Ensemble, a website, an app, AI software, or a brand exercise.

## 2. Current ChatGPT execution boundary

Temporary Chat is not the default renderer because image generation has been observed unavailable there in the user's current ChatGPT configuration.

Default Renderer Context:

> **A new regular chat outside the Ensemble project.**

Preferred laboratory discipline:

> **One generated image per Renderer Context, then close that renderer chat.**

For an orthogonal experiment, open another fresh Renderer Context rather than allowing a renderer conversation to accumulate its own local visual history.

> **Creative intelligence persists. Rendering context expires.**

## 3. Narrowed claim after R0 evidence

Renderer Isolation materially changed early outputs and remains useful, but Cross-Surface Robustness Experiments 01–04 demonstrated that a fresh non-project renderer can still converge on repeated learned visual shortcuts.

Therefore Renderer Isolation should be understood as:

- reducing known project-context inheritance;
- preventing historical project files/images/prompts from being directly supplied to the renderer;
- keeping each generation locally short-lived;
- improving experimental hygiene.

It does **not** prove:

- mathematically memory-free generation;
- absence of account-level product context that cannot be independently inspected;
- absence of base-model semantic or aesthetic priors;
- that open-ended prompts will yield orthogonal visual grammars.

## 4. Saved-memory and chat-deletion clarification

Saved-memory controls are not the project's visual-continuity or visual-isolation mechanism.

Do not spend render budget on memory-negation preambles such as:

- "ignore all memories";
- "do not use personalization";
- "start with no image memory."

Those sentences do not provide a verifiable control and add irrelevant prompt content.

Project continuity remains GitHub/Drive-based. Renderer isolation remains a context-separation method, not a proof about hidden model state.

## 5. Director Context responsibilities

The persistent Ensemble/Kymaean Director Context may and should know:

- `Rylascoo/Ensemble-Website` current state, design law, active evidence, and renderer research;
- `Rylascoo/Ensemble-Project` current product truth and validation boundaries;
- Google Drive `Ensemble Project` visual masters, registry, archive, and critique history;
- O0 and later historical branches;
- historical favorites, failures, user reactions, and design judgments;
- prior generated artwork when evidence review or deliberate comparison requires it;
- the complete evaluation framework and project vocabulary.

The Director Context should not generate clean-slate artwork directly by default.

Its job is to:

1. define the research question;
2. identify the semantic kernel that must survive;
3. identify the formal variable/grammar being tested;
4. construct a bounded renderer packet;
5. recursively audit the packet and transfer surface;
6. under the standing delegation, treat a clean pass as earned approval;
7. send only the approved bounded inputs to a fresh Renderer Context;
8. evaluate the returned artwork;
9. archive visual evidence and critique;
10. update project authority only after the relevant recursive audit is clean.

## 6. Renderer Context restrictions

For normal generation, the renderer should:

- have no project files except an explicitly authorized sanitized structural reference for a controlled transfer experiment;
- receive no Kymaean/Ensemble design documents;
- receive no historical Kymaean artwork unless a deliberate reference-transfer experiment requires one;
- receive no project-chat continuity in its prompt;
- receive no previous renderer prompt unless a contrastive experiment intentionally holds it constant;
- receive no example menu merely to explain creative freedom;
- have the shortest practical lifetime.

After generation, return the image to Director Context for evaluation and archival.

## 7. Sterile packet law

A sterile packet is the normal transfer unit. "Sterile" means free of irrelevant project-history contamination, not artistically unconstrained.

Do not include, unless indispensable to a deliberate experiment:

- Kymaean;
- Ensemble;
- Human Causality, Living Consequence;
- AI/app/website/branding/visual-identity terminology;
- historical branch names;
- project documents;
- previous artwork descriptions;
- scoring rubric or critique history;
- long historical motif blacklists.

A controlled formal or structural reference may be transferred only when the active experiment package explicitly defines the transferred variable and its contamination test.

## 8. Examples remain visual seeds

Concrete examples offered merely to explain an open invention space are not neutral.

> **Do not give examples of what the renderer is free to invent unless the example is intentionally being selected as a seed.**

This includes settings, objects, mechanisms, cultures, media, materials, architecture, clothing, occupations, historical eras, narrative situations, and named visual genres.

## 9. Prompt accumulation and contrastive control

Appending corrective prose to an earlier prompt does not guarantee a reset.

For a genuinely new experiment, use a fresh renderer chat and a newly derived packet.

For a contrastive experiment, deliberately preserve the baseline packet and change only the targeted variable.

> **Uncontrolled rewrite for novelty is not the same as controlled variation for learning.**

## 10. Causal and artistic laboratories remain distinct

Do not demand that every image simultaneously prove the full product thesis and discover the brand aesthetic.

Maintain separate evaluation lenses where useful:

- **Causal Physics:** evidence, consequence, changed state, asymmetric understanding, present traces of human action.
- **Artistic Language:** human structural importance, relationship as visual geometry, identity persistence, partial visibility, abstraction, material behavior, emotional magnetism, and visual authorship.
- **Renderer Cartography:** which prompt variables reliably alter which visual behaviors, attractors, and formal properties.

Cross-lab synthesis happens only after evidence exists.

## 11. Artwork-only execution contract

Unless an experiment intentionally studies typography or collateral, request one uninterrupted artwork.

Do not include logos, wordmarks, marketing copy, explanatory captions, website/app UI, presentation boards, moodboards, comparison grids, palette swatches, experiment titles, or branding panels.

If collateral appears anyway, classify it as execution-failure evidence before evaluating transferable visual discovery.

## 12. Evaluation gates

For causal experiments, evaluate before beauty:

1. person-removal test;
2. evidence test;
3. changed-state/possibility test appropriate to the experiment;
4. unequal-understanding test where relevant.

For artistic-language experiments, ask whether people are structurally necessary, relationships alter the visual field, individuals remain specific, identity can persist through transformed representation, and the result feels authored rather than like a learned genre shortcut.

For Renderer Cartography, additionally record controlled variables, predicted effect, observed effect, unintended changes and attribution confidence.

## 13. Recovered attractor laws

Prior RI/AL, Round 1, and Cross-Surface evidence established that:

- broad invented-world language can activate generic cinematic concept-art priors;
- over-specified narrative objects can make medium/style rhyme literally with story;
- material-history vocabulary can activate rustic craft-world imagery;
- history does not require age, patina, ruin, dirt, or handcraft;
- beneficial changed-access scenarios can activate civic/accessibility illustration shortcuts;
- abstract pair/mechanism language can become monumental symbolic machinery;
- open relational drama can drift toward period-coded painterly melodrama;
- monumental architecture and bridges/thresholds can recur even in fresh non-project renderer chats;
- learned semantic priors therefore remain an experimental variable after project isolation.

Do not confuse history with age, humanity with handcrafted patina, consequence with damage, benevolence with accessibility accommodation, originality with cinematic worldbuilding, abstraction with monumentality, or changed relationship with a literal bridge/door/wall metaphor.

## 14. R0 system hypothesis remains non-aesthetic

Current non-aesthetic system hypothesis:

> **Distinct people are structurally important; human choices can change shared conditions and future possibilities; identities can persist across transformed representations; relationships can structure the visual field; visibility/access can be asymmetric; and present arrangements can contain evidence of prior human causes.**

Historical shorthand such as `We inherit boundaries. We create crossings.` creates no visual inheritance rights.

> **Clean recursive audit = earned approval for a design-lane gate.**

A renderer/reference-transfer/image-generation gate that reaches a clean recursive audit is recorded as:
