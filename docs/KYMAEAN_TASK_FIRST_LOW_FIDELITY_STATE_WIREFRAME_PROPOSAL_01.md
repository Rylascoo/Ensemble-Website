# KYMAEAN TASK-FIRST LOW-FIDELITY STATE WIREFRAME — PROPOSAL 01

Status: DIRECTOR PROPOSAL FOR REVIEW / NO PRODUCTION IMPLEMENTATION AUTHORIZED

Phase: Kymaean App + Website Design Synthesis — interaction validation

## Purpose

This proposal translates the approved task-first interaction prototype into semantic states. It is not a visual design, final wireframe, XAML specification, or component decision.

The goal is to test whether the shell principle:

> Stable Production, fluid focus.

can survive actual user movement.

## State 0 — Enter Production

Question tested:

Can the creator understand where they are before interacting?

Required understanding:

- current Production identity;
- current Scene/context when available;
- current perspective/disclosure state when relevant;
- whether the user is viewing current material or historical/proposed material.

Avoid:

- dashboard-first experience;
- exposing every possible system concept before a task exists.

## State 1 — Current Performance Focus

Purpose:

The creator experiences what is happening now.

Primary test:

Does the human situation remain primary?

Required:

- people and relationships remain legible;
- relevant action/agency is understandable;
- available intervention follows context.

Avoid:

- turning the experience into a timeline viewer;
- replacing people with metadata panels.

## State 2 — Context Inspection

Purpose:

The creator asks: "Why is this happening?" or "What conditions matter?"

The inspection surface must preserve the relationship to the current focus.

It may expose:

- relevant possibility conditions;
- relationships;
- unresolved pressures;
- bounded context.

It must not:

- become a permanent information warehouse;
- imply that inspected information changes authority.

## State 3 — Causal Trace

Purpose:

The creator asks: "What changed this?"

Required distinction:

```text
history inspection
!=
rewinding reality
```

The state must communicate:

- what became effective;
- what remains proposed/unresolved;
- why the current condition exists.

## State 4 — Intervention

Purpose:

The creator changes an allowed condition or direction.

The prototype must test:

- creator authority boundaries;
- command discoverability;
- explicit confirmation where authority changes matter.

Avoid:

- accidental mutation through navigation;
- ambiguous AI-generated changes.

## State 5 — Bounded Character Perspective

Purpose:

Test Presentation Perspective.

Question:

Can the same Production become a different experience without becoming a different reality?

Required:

- disclosure changes;
- authority does not change;
- unavailable knowledge remains unavailable.

## State 6 — Consequence Recognition

Purpose:

The creator sees that an accepted event altered future possibility.

This is the critical Kymaean moment.

The product must communicate:

```text
something happened
+
that changed something else
+
future options are now different
```

Avoid:

- ending on a static report;
- treating consequence as a log entry only.

## State 7 — Return to Present

The final state returns to the changed Production.

Success condition:

The creator feels continuity, not navigation completion.

The user should understand:

- where they are;
- what changed;
- what is now possible.

## Validation criteria

A successful prototype should demonstrate:

1. One persistent Production context.
2. Clear current/history distinction.
3. Meaning-linked transitions instead of page tourism.
4. Human primacy over system display.
5. Accessible sequential navigation.
6. Quiescent behavior when no state changes.
7. No dependency on final branding, art direction, animation, or AI capability.

## Explicit non-goals

This proposal does not select:

- final visual style;
- app icon;
- typography;
- color system;
- WinUI controls;
- Stage/Studio/Archive labels;
- Take/branch/rehearsal semantics;
- Character Context ontology;
- production implementation.

## Director review gate

Question:

> Does this state sequence preserve the feeling of one living Production while making causal change understandable before visual refinement begins?
