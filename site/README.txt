ENSEMBLE WEBSITE / KYMAEAN — PUBLICATION SOURCE BOUNDARY

Status: ACTIVE PUBLICATION ROOT / NO PRODUCTION SITE SELECTED OR DEPLOYED
Updated: 2026-09-08

PURPOSE
`site/` is the single deployable/public website data-plane boundary in `Rylascoo/Ensemble-Website`.

Everything required to build or deploy the public Kymaean website must eventually live inside this subtree or be generated by tooling that also lives inside this subtree. Repository research, evidence, prototypes and control-plane material do not become deployable by proximity.

CURRENT LAW
- `site/` is publication source only; it is not a design-research workspace.
- `prototypes/` remains experimental/renderable research evidence and is never production source by implication.
- `assets/` remains repository asset storage. Required public assets must be deliberately promoted/copied/processed into the site project rather than referenced through `../assets`.
- `docs/`, `tools/`, `intelligence/` and `updates/` are non-deployable repository/control surfaces.
- No historical prototype is copied, moved, renamed or promoted into `site/` merely to populate this directory.

CLOUDFLARE WORKERS BUILDS CONTRACT
Once a deployable website source is explicitly authorized:

1. Connect Cloudflare Workers Builds to the authoritative repository branch `main`.
2. Set the Worker root directory to `site/`.
3. Restrict build watch inclusion to `site/**` when that setting is available.
4. Put any `wrangler.toml`, `wrangler.json` or `wrangler.jsonc` for the public website inside `site/`, never at repository root.
5. Keep the site project self-contained. Production source/configuration must not reach outside the subtree for `../docs`, `../prototypes`, `../assets`, `../intelligence`, `../updates` or `../tools` dependencies.
6. Select the framework/build output and any static-assets directory only when the production implementation is authorized. Do not pre-commit a fake `public/`, `dist/` or Worker entrypoint solely to satisfy deployment tooling.

BRANCH MODEL
A permanent branch named `site` is not the deployment boundary and is not current authority. New website work starts from current `main` on a scoped branch such as `site/<work-package>`, then merges back to `main` after recursive audit and required validation. Cloudflare isolation comes from the `site/` root directory and watch paths.

DEPLOYMENT GUARD
There is intentionally no production `index.html`, package manifest or Wrangler configuration in this directory at this checkpoint.

Do not point production Cloudflare at repository root or `prototypes/`. Do not deploy this empty boundary merely because it is structurally ready.

WEBSITE UPDATE FLOW
Non-executable planning/change/release records belong in `updates/`. The implementation itself belongs here in `site/`. After production source is selected, every website release should be traceable from an `updates/` record to the exact `site/` commit deployed.
